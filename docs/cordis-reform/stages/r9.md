# R9 — 删除 Pi

状态:设计稿
对应计划:`../implementation-plan.md` 第 13 节;`../target-architecture.md` 第 22 节
上游引用:R8 的删除清单与导出设计;R0 拍板的"破坏性处理需最终单独确认"

## 目标

到达最终的单引擎 Cordis 架构:无 Pi 运行时依赖、无兼容面、无死代码。
R9 是**独立授权**的破坏性阶段——进入本阶段前必须重新获得用户显式批准,
R8 的完成不构成对 R9 的授权。

## 执行顺序(严格按序,每步可独立评审)

1. **备份与导出**:构建并验证项目备份;按 R8 设计生成可选的 Pi 转录静态导出,
   用 fixture 验证导出可读;
2. **摘除引擎选择**:从引擎选择器移除 Pi,禁用 Pi 会话的创建/启动命令;
   既有 Pi 会话此时转为只读归档视图(在破坏性迁移执行前仍可读);
3. **删除 Renderer Pi 面板**:面板、状态、replay、订阅、IPC 调用;
4. **删除 Main 侧 Pi 编排**:legacy session/loop/context/prompt/compaction/queue;
5. **删除 worker**:`agent-worker` 入口、`AgentModelClient`、Pi 运行时/provider adapter、
  worker 协议;
6. **删除共享契约**:不再有产品消费者的 legacy Agent 运行时契约与通道定义;
7. **删除依赖**:manifest 与 lockfile 移除 `@earendil-works/pi-agent-core`、
  `@earendil-works/pi-ai`;反向依赖分析证明 TypeBox 无其他消费者则一并移除;
8. **删除 `pi-legacy` shell 分支**:Cordis 成为唯一 Agent 功能,引擎选择器本身移除;
9. **破坏性数据迁移**(单独授权点):删除 legacy Pi 会话/运行/事件表;
   若用户选择保留,则转为**显式有界**的只读归档 checkpoint(表保留、无写入路径、
   有明确的最终移除期限),两种分支都必须先完成备份、完整性检查与用户确认;
10. **删除 legacy 测试**:先替换掉它们独有承担的产品级覆盖(按 R8 清单),再删文件;
11. **文档收口**:architecture、ADR supersession 注记、current-plan、tracker、history、
    打包清单、诊断说明、恢复 fixture 全部更新;引擎选择器相关文档删除。

## 不可协商的证明

仓库范围扫描必须为零(Runtime 面;历史迁移与冻结文档中的旧名字除外):

```text
0 runtime imports of @earendil-works/pi-agent-core
0 runtime imports of @earendil-works/pi-ai
0 legacy agent-worker entrypoints
0 Pi session/run/event IPC channels used by the product
0 Pi session/event SQL used by the product
0 Pi engine branches in Renderer
```

扫描目标是 Pi 会话/运行/事件运行时,不是所有带 `agent` 前缀的标识符。以下平台存活物
被显式排除:

- app.sqlite 的 `agent_model_catalogs`、`agent_model_preferences`、`agent_provider_preferences`、
  `agent_skills` 表;
- 审批模式 app 设置通道(`app:get/set-default-agent-approval-mode`);
- provider 预设/凭证通道(`providers:*Agent*`);
- 仅带 Pi 时代命名的平台代码——由 R4–R7 维护的中性化改名清单保证扫描零误报。

## 最终门槛

- 无 Pi 包的 frozen install 成功;
- `check:fast`、Electron 全套测试与构建、全部恢复 fixture、全部 E2E、每个受支持平台的
  package 门、native module 检查、ASAR/资源清单、打包 smoke 全绿;
- 清洁安装、Pi 时代项目升级、备份还原、静态导出、破坏性 cutover 恢复五条路径验证通过;
- cutover 前后项目数据库 `integrity_check` 均通过;
- 无兼容 adapter、无死代码残留;
- 用户显式接受最终删除证据。

## 回滚

**没有代码级 fallback。** 恢复手段是还原完整的 cutover 前应用构建与项目备份。
这正是 R9 必须独立授权、且破坏性数据处理不与 R8 捆绑的原因。

## 风险

| 风险 | 控制 |
| --- | --- |
| 误删平台共享代码/数据 | 中性化清单 + 平台存活物排除名单进扫描规则;删除 diff 执行前评审 |
| 删除后才发现某产品覆盖仅由 legacy 测试承担 | R8 清单的"测试独有覆盖"项先行替换;R9 第 10 步按清单核对 |
| 用户事后需要 Pi 转录 | 备份 + 静态导出已在第 1 步验证;导出文件头标注 archival-only |
| TypeBox 误删 | 反向依赖分析证明零消费者才移除,否则保留并记录原因 |
