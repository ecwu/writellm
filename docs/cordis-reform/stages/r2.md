# R2 — 独立进程骨架与引擎 shell

状态:设计稿
对应计划:`../implementation-plan.md` 第 6 节;`../target-architecture.md` 第 6、7、12 节
上游引用:cordis core API(`Context`/`plugin`/`Service`/`effect`/isolate,见 r1.md 的
conformance 冻结);仓库现有进程承载 `src/main/workers/persistent-utility-process.ts`、
worker 装配 `src/main/index.ts`、通道定义 `src/shared/contracts/channels.ts`、
preload `src/preload/index.ts`

## 目标

建立全部三个 Cordis 进程上下文(Main / cordis-agent-worker / Renderer)与
Cordis Host Protocol v1,让 UI 可以选择一个**不可用但可诊断**的 Cordis 引擎,
同时不与 Pi 运行时共享任何东西。R2 结束时没有会话能力——那是 R3——但进程、协议、
shell、诊断和回滚路径全部就位。

## 设计细节

### 1. `cordis-agent-worker` 进程入口

- 新增 Electron utilityProcess 入口,承载方式复用现有
  `persistent-utility-process.ts` 的模式(消息端口、生命周期监督、崩溃重启钩子),
  但与 `agent-worker` 是**两个独立入口文件、两个独立进程实例**;
- worker 内建立 context 树:`worker root Context → project runtime realm`
  (架构 §7.2)。R2 的 worker 只装载进程安全的最小服务:日志、clock、correlation、
  host-protocol client;不装载 loop/llm/tools(R3 起);
- worker 的 Loader 装配序列沿用框架形态:`new Context()` → 设 `baseUrl` →
  `await ctx.plugin(Loader)` → `ctx.loader.create({ name: include, config: { path } })`;
  生产装配的入口配置文件是内置可信 catalog 生成的只读配置(见 r1.md §2);
- worker **没有任何项目路径或数据库句柄**:boot 命令只携带 project 安全标识与
  capability,不携带绝对路径;import-boundary 测试机械保证 worker 包不含数据库/
  文件系统模块。

### 2. Cordis Host Protocol v1

Main↔worker 的 MessagePort 协议,Zod 双向校验。本阶段冻结 envelope,只实现
boot/dispose/诊断类命令;会话与运行命令在 R3 接入实现,但 envelope 字段必须现在就位,
因为它是全部后续 seam 的形状。

envelope 字段(每条消息):

```ts
interface HostEnvelope {
  protocol: 'cordis-host/1'
  kind: string                    // 命令/请求/响应/事件种类,闭集
  requestId: string               // 单次使用;响应与原请求严格一一对应
  operationId: string             // 关联到 Main 的操作关联链
  trace: { traceId: string; parentSpanId?: string; flags: number }  // 仅标识符,无 span 模型
  projectId: string               // 安全标识(非路径)
  capability: { projectSessionId: string; epoch: number }  // 每条项目级消息重新校验
  sessionId?: string; runId?: string; turnId?: string; stepId?: string; callId?: string
  payload: unknown                // 按 kind 闭合的 Zod schema,有字节上限
}
```

协议不变量(全部进 property 测试):

- MessagePort 安装时完成发送方角色认证;
- 每条项目级消息重新校验 capability epoch,撤销后的迟到消息拒绝并安全记录;
- requestId 单次使用,响应恰好关联一次;取消双向显式链接;
- 超时不遗弃在途工作——owner 到达 quiescence 后才 dispose(架构 §18.2);
- 原始错误先以 `err` 记入日志(含 correlation),再转换为 sanitized 传输错误;
- payload 永不包含绝对项目路径或明文凭证(provider lease 的窄通道在 R3 定义)。

命令面(R2 只实现标注 ★ 的):

- Main→worker:★ boot project realm、★ dispose project realm、open/close session、
  start run、steer、enqueue、delete pending input、abort、compact、update session settings;
- worker→Main:★ 诊断自报(composition revision、Fiber 清单)、append durable event、
  load event page、store request snapshot、begin/complete model audit、
  execute authoritative tool、request approval、flush。

### 3. Main 侧骨架

- Main Cordis root Context + 每个活跃 `projectSessionId` capability epoch 一个
  project Context(架构 §7.1);root 拥有日志、clock、boot 诊断、IPC 注册、worker client;
- 新增 `cordis-agent:*` IPC 命名空间与 preload namespace,全部输入输出经 Zod 校验、
  sender 授权、capability 校验(与现有 `agent:*` 同一安全标准);
- R2 的 IPC 面:引擎可用性查询、composition/诊断读取、default-engine 设置读写;
  不出现任何会话命令。

### 4. Renderer:引擎 shell 与面板抽取

- 新增 `src/renderer/src/features/agent-engine-shell/`:
  `AgentEngineId = 'pi-legacy' | 'cordis'`、引擎选择器、default-engine 设置入口、
  tagged session handle(`{ engine, sessionId }`,shell 不接受无引擎标签的 sessionId);
- **面板抽取**(评审轮补的工作项):把现有 Agent 面板
  (`features/agent/agent-panel.tsx`,深嵌在 `manuscript/writing-workspace.tsx`)包成
  shell 的 opaque engine entry——现有面板与 `agent-proposal-actions`、review workbench、
  quick actions 的接线改为经 shell 路由,**行为逐字节不变**,现有 agent E2E 不改断言通过;
- 新增 Cordis client root Context:**仅 cordis core 运行时**,无 Loader/Include/Group/HMR,
  UI 组成构建期固定,运行时只做 enable/disable 投影(架构 §5.2/§7.3)。
  框架事实支持这一划分:cordis core 的运行依赖只有 cosmokit 与 standard-schema
  (纯 JS、`sideEffects: false`),无 Node-only API;Node-only 的是装配层
  (loader/include/hmr)。dsh 浏览器侧同样不跑 Loader,而是用 client 装配元数据
  + runner——与我们"构建期固定 UI 组成"的决定同构;
- Cordis 面板在 R2 只有一个诊断/不可用态页面;引擎在能创建会话前隐藏在
  experimental availability gate 之后。

### 5. 只读诊断

- Main 与 worker 各自投影 live registry:进程、composition revision、plugin entry 状态、
 未满足依赖(PENDING)、上次 reload 结果;R1 的 inventory 投影在真实进程里接通;
- correlation/trace 标识符跨 Renderer/Main/worker 的测试命令传播,断言在 malformed 与
  late-message 路径上存活;**本阶段不建 span 模型、sink 或 trace UI**(架构 §19.1 状态注记)。

### 6. 隔离 gate(机械执行)

- 现有 `agent:*` 通道与 `agent-worker` 行为逐字节不变;
- Cordis worker 无法访问项目路径或数据库;
- Renderer bundle 不含 Cordis Main/worker 实现、不含 Loader 族包、不含 Node 权限;
- 两个面板之间不存在共享的 event/session/run 类型。

## 测试计划

- Host Protocol:schema/property 测试(随机 envelope、乱序、重复 requestId、epoch 撤销)、
  malformed-message 测试、取消链路测试;
- 进程:反复 open/close/reopen 泄漏测试;worker 崩溃/重启;partial boot 清理;
  capability 撤销后的迟到消息拒绝;
- 跨进程 trace-parent 与 disposal 测试;
- Renderer IPC sender 授权测试;bundle 审计(无 Node/Loader 族);
- `check:electron`、fresh 关键 E2E、`check:package`(新增 worker 入口触发打包门)。

## 验收门槛

- 隔离 gate 六条全部机械通过;
- UI 可以选择 Cordis 引擎并看到不可用/诊断态,Pi 行为不变;
- 崩溃/撤销/迟到消息路径全部确定性清理;
- Pi Agent 测试与 E2E 不改断言通过。

## 回滚

把 availability gate 置 false,移除独立进程/shell 分支。Pi 全程不受影响。

## 风险

| 风险 | 控制 |
| --- | --- |
| Host Protocol 欠规格(它是引擎轴心) | envelope 在 R2 冻结;property 测试先行;后续阶段只加 kind 不改 envelope |
| 面板抽取引入行为漂移 | 抽取单独成 PR,现有 E2E 不改断言;逐字节行为对比 |
| worker 监督逻辑复制粘贴 Pi 版本导致耦合 | 承载模式复用但入口独立;共享代码只允许引擎中立平台层 |
| 三进程 context 树过度设计 | R2 只建骨架与诊断,不预建 R3+ 的服务;按阶段生长 |
