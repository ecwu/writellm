# R8 — Cordis 默认化与删除资格

状态:设计稿
对应计划:`../implementation-plan.md` 第 12 节;`../target-architecture.md` 第 18.4 节
上游引用:parity 证据全部来自 R3–R7 的验收产出;本阶段不引入新的外部依赖

## 目标

把新会话的默认引擎切到 Cordis,同时把 Pi 保留为显式 fallback,**只用足够长的时间收集
删除证据**。R8 的本质是一个证据收集阶段:它不改变任何运行时行为,只改变默认值,
并把"能否删除 Pi"变成一个可逐项核对的事实问题。

前置条件:§15 平价矩阵 21 行(含评审轮新增的 Composer UX 与 Quick actions 两行)
全部完成,否则 R8 不得开工。

## 工作项

### 1. 默认引擎切换

- `agent.defaultEngine` 对新安装与既有项目迁移均设为 `'cordis'`;
- **尊重显式选择**:用户显式改过默认引擎的安装,迁移不覆盖其选择,仅在设置界面把
  Pi 标记为 legacy;默认值迁移只影响从未表达过偏好的用户;
- 引擎选择器保留,Pi 面板可用但标注 legacy;会话手柄仍按 `{ engine, sessionId }`
  路由,行为不变。

### 2. 清洁安装与升级项目矩阵

两组矩阵都要跑通,覆盖:

- 清洁安装:新建项目 → 默认 Cordis → 完整写作工作流;
- 升级项目:含 Pi 会话历史、提案、评审、任务、资产的项目打开后,Pi 会话仍可读可继续,
  新会话默认 Cordis,产品数据(proposals/revisions/tasks/reviews/assets)完整无损;
- 每个支持的打包目标(macOS 先行,按发布矩阵)重复上述。

### 3. 删除证据演练(全部在 Cordis 上)

- 真实配置 provider 的长会话(数十轮、含 compaction);
- 全部提案种类(brief/writing rules/outline/section/image)的提交、审批、应用、undo、refresh;
- 中断(用户 abort)、项目重开、worker 崩溃重启后的恢复;
- 打包升级场景:旧版本应用数据由新版本打开;
- 重复关闭/重开与崩溃测试证明无泄漏 effect、无半提交(贯穿 R3–R7 的 gate 在此汇总复跑)。

### 4. 删除清单(deletion inventory)

产出一份机器可核对的清单,逐项列出 Pi 的:

- runtime import(`@earendil-works/pi-agent-core`、`@earendil-works/pi-ai` 的全部引用点);
- manifest/lockfile 依赖条目(含 TypeBox 的反向依赖分析);
- IPC 通道(`agent:*` 中属于 Pi 会话/运行/事件面的部分;平台存活物——app 级
  `agent_*` 表、审批模式 app 设置通道、provider 预设/凭证通道——按中性化清单排除);
- 数据库表与迁移(`agent_sessions`/`agent_runs`/`agent_events` 及其历史迁移);
- worker 入口与协议文件;
- Renderer 面板、状态、replay、订阅代码;
- 测试文件与哪些产品级覆盖由它们独有(删除前必须替换);
- 打包资源与文档引用;
- R4–R7 维护的**中性化改名清单**(`pi-credential-store` 等平台代码的 Pi 时代命名),
  使 R9 的扫描可以要求零命中而不误报。

### 5. 归档导出设计

为需要保留 Pi 转录静态副本的用户设计一次性导出:

- 每个 Pi 会话导出为静态 JSON(完整事件)与/或可读 Markdown(消息与提案决策);
- 导出是**归档输出**,不是可运行的兼容格式;明确不支持重新导入为 Cordis 会话;
- 导出设计在 R8 评审,R9 执行前必须可用并经 fixture 验证。

## 删除资格门槛(全部满足才可提出 R9)

- Cordis 是默认引擎且平价矩阵每一行完成;
- 没有任何被接受的工作流必须选择 Pi;
- 每个仍在 provider 设置里 advertised 的 Agent 协议都有 Cordis 适配器,或有经批准的
  移除决定;
- 无遗留的 P0/P1 Cordis 正确性、数据丢失、安全或恢复缺陷;
- 重复项目关闭与 worker 崩溃测试无泄漏 effect、无半提交;
- 升级项目 fixture 的产品数据(提案、修订、任务、评审、资产)保留完整;
- 全部受支持打包目标通过;
- 精确的 Pi 删除 diff 在执行前已评审;
- 用户显式授权破坏性遗留数据处理(R0 拍板的最终确认在此兑现)。

## 回滚

把默认引擎改回 `pi-legacy`。无需任何数据转换——双引擎隔离保证了这一点。

## 风险

| 风险 | 控制 |
| --- | --- |
| 默认切换后 Pi 回归无人发现 | Pi 面板保持可用;双引擎 golden 场景在 CI 等价物中持续运行至 R9 |
| 删除清单遗漏导致 R9 中途返工 | 清单机器可核对(grep/扫描脚本),R8 评审时逐项演示 |
| 导出设计被误解为可迁移格式 | 文档与导出文件头明确标注 archival-only |
