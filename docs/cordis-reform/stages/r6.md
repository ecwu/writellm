## 目标

让全部**改变产品状态**的工具通过 R4 的引擎中立 Main 权威在 Cordis 引擎落地。
前置:R4(权威)与 R5(读工具与快照绑定)已验收。R6 之后,Cordis 引擎在功能上
可以独立完成现有 Agent 的全部写作协作工作流。

## 设计细节

### 1. 工具与权威映射

| 工具 | Main 权威 seam | 现有实现参照 |
| --- | --- | --- |
| `record_review_issues` / `update_review_issues` | `writellm.reviewIssues` | `review-issue-service.ts` |
| `create_writing_task` / `update_writing_task` | `writellm.writingTasks` | `writing-task-service.ts` |
| `submit_brief_change` / `submit_writing_rules_change` / `submit_outline_change` / `submit_section_change` | `writellm.changeProposals` | `mutation-service.ts` |
| `generate_image` | `writellm.imageGeneration` + proposals | `model-execution-service` 的 ImageGenerationGateway → worker `auxiliary-model-request.ts` |
| (R5 已交付)`inspect_change` 只读形式 | `writellm.changeProposals` | — |

提案的 inspect/refresh/reject/apply/undo 与 change-set 批量是 **Renderer 审批 UI 调用的
Main 产品权威操作**,不是模型工具;它们经 `cordis-agent:*` IPC 走同一权威。

### 2. 提交管线(durable 优先,架构 §9.4)

```text
模型 tool call
  -> 提交 durable tool/call(Main 分配 event id/序列号/时间戳)
  -> tools/pre-execute waterfall(allow/deny/ask 与参数策略)
  -> 已注册的单调收紧 guard(审批/权限;只可收紧,不可放宽)
  -> tools/execute waterfall(timeout/metrics/tracing -> Main 权威 RPC)
  -> tools/post-execute waterfall(检查/约束/丰富/阻断结果)
  -> 归一化并校验结果
  -> 提交 durable tool/result
  -> emit live tools/result -> Renderer 投影
```

铁律:**任何变更或外部作业在其 `tool/call` 与来源模型请求持久化之前不得成为权威。**
提案工具只有在产品提案行与对应 Cordis 事件引用一致提交后才返回。

### 3. 提案生命周期与来源绑定

- 模型参数**永远不选择** Main 必须绑定的权威 ID 或版本:submit 工具只携带意图与内容,
  Main 在提交时绑定 source snapshot ID(R5 的 canonical read 快照)、当前源版本、
  产品 ID;过时或冲突的变更直接失败,不产生半记录的变更;
- 每个提案记录 `AgentOrigin{ engine:'cordis', sessionId, runId, toolCallId }` 与
  immutable source snapshot 引用;
- 当前产品策略(ADR 043/044)决定自动应用还是进入评审;**live mode 在提案裁决时
  重新读取**,与 ADR 044 一致;
- Renderer 审批(reject/apply/undo/refresh、change-set 批量)直接调 Main 产品权威,
  不经 worker;Main 提交结果后向 worker 发 durable 事件/outbox 回执,
  **worker 在决策提交后才恢复**该工具调用。

### 4. 审批策略与暂停/恢复机制

- 策略值保留产品语义 Manual / Write Auto(契约值 `section_auto`)/ YOLO;
  Cordis 会话持有自己的设置与 durable 策略变更事件;
- 策略 listener 只能收紧:任何后续插件不得把 deny 变 allow、把要求评审变成静默执行
  (实现形态:`tools/guard` 链全局先、scope 链由远及近,首个 deny reason 赢);
- 审批裁决本身是 fail-closed 的(dsh 同款):`approval/request` 的 answerer 缺省、
  抛错或返回越纲值一律按 `unavailable` 处理;`ask` 决策只有 `allowed-once` 放行;
  无 approval 服务或无 agent 上下文时 `ask` 退化为 deny;policy 为 never 时在
  dispatch 前确定性短路;durable 的 `approval/asked` 与 `approval/decided`
  审计对必须被 open turn 包住(缺 turn 即装配错误);
- **暂停/恢复机制做成卡片类型无关**(为延期的 userQuestions 阶段预留关节,架构 §3.3):
  挂起 = 提交 durable `approval/asked`、通知 Renderer、worker 等待;
  恢复 = Main 提交 `approval/decided`、worker 继续;问答案片复用同一骨架但走
  `question/*` 事件族(本阶段不实现);
- 审批取消、项目关闭、worker 崩溃时的确定性结局:durable 日志驱动恢复,
  无半应用状态(架构 §18.3)。

### 5. 图像生成

- 保持后台 worker 作业形态:Main 经 ImageGenerationGateway 派发,产出**一个**
  有界资产/提案结果(ADR 029 的 candidate lineage 语义不变);
- 取消走 `cordis-agent:*` 的取消通道;作业失败/取消后无残留资产引用;
- 图像作业与提案提交遵循同一事务/outbox 规则。

### 6. 事务与 outbox

- 产品权威事务只含本地 SQLite:源版本校验、提案状态迁移、revision/brief/outline/asset
  结果、undo/refresh lineage;
- 引擎事件若不能与产品事务同事务提交,则在该事务内写入 durable outbox 行,
  幂等 drain;日志永远不当 outbox 用(架构 §11.3)。

## 测试计划

- 每个工具的契约测试:合法/非法参数、过时快照、冲突版本、取消、未授权、provider 错误;
- Main 事务测试:提案决策的原子性、undo/refresh lineage、outbox 重放幂等;
- 恢复测试:项目关闭、审批取消、worker 崩溃、图像作业失败,均无半应用状态;
- 双引擎:Pi 与 Cordis 提案共存、按 origin 可区分、经同一乐观产品规则解决并发冲突
  (不是共享运行时锁);
- E2E:全部变更/协作场景的 Cordis 版本 + 引擎参数化双跑(R5 建的机制);
- `check:electron`、全部恢复 fixture、E2E、`check:package`。

## 验收门槛

- 现有全部变更/协作功能在 Cordis 有 unit、Main 事务、恢复、IPC、Renderer、E2E 覆盖;
- 无任何产品变更在 durable 事件之前成为权威;
- 策略单调收紧有合同测试(试图放宽的插件被拒绝并留诊断);
- 全部打包与恢复门通过。

## 回滚

默认引擎切回 Pi 并禁用新 Cordis 运行。**已提交的产品变更不回滚**——它们是普通的
权威项目历史,不因发起引擎被禁用而撤销。

## 风险

| 风险 | 控制 |
| --- | --- |
| 模型参数被当成权威 ID 使用 | submit 工具 schema 不含权威 ID 字段;Main 绑定在合同测试固定 |
| 审批暂停/恢复与崩溃路径交织出错 | durable 事件驱动恢复;崩溃/取消/关闭三路径各有 fixture |
| outbox 与产品事务分叉 | 同事务提交;对账测试覆盖重放与幂等 |
| 策略插件意外放宽审批 | 单调收紧进合同测试;违规注册在装配期失败 |
