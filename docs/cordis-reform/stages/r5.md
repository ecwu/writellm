## 设计细节

### 1. Prompt contribution 模型(结构化,不是文本 hook)

借 dsh `systemPrompt` 的形态,五类贡献分离:

| 贡献类型 | 模型可见角色 | 约束 |
| --- | --- | --- |
| `section` | 稳定指令与策略 | 具名、有序、按 scope;可同步或延迟求值 |
| `context` | 独立排序的上下文贡献 | 与 section 不同的排序带 |
| `variable` | section 引用的小型类型化值 | 命名受限、按 scope 解析;未解析即装配失败 |
| `tools` | 模型可见工具名与 schemas | 精确有序 schema 进请求快照 |
| `complete` | 刻意整体替换的专用模式 | 唯一、显式标识;waterfall 之后再次强制落实,普通插件不能暗中替换 prompt |

注册契约:每项贡献有稳定 contributor ID、owner plugin ID、order、scope、revision、
sensitivity class 与 disposer(由注册 Fiber 的 effect 持有)。覆盖规则(dsh
ScopedLayers):**同层重名抛错**,更具体 scope 的同名注册 shadow 全局项,variable
取最近 scope;排序确定且稳定(order 升序,约定 -100=平台身份、0=产品 persona、
100-199=工具指导)。重复 exclusive provider、非法排序、未解析变量、超预算输出 →
在 provider I/O **之前**装配失败。变量插值是严格的 `{{name}}` 形态:未知或畸形
变量直接抛错,不做静默留白;空 section 丢弃,section 间以 `\n\n` 连接。

注册 API 形态(参照 dsh,全部返回 effect disposer):

```ts
ctx.systemPrompt.section({ name, order, text: string | ((ctx) => string), complete? })
ctx.systemPrompt.context({ name, order, text })
ctx.systemPrompt.tools(provider => ({ schemas, knownNames? }))
ctx.systemPrompt.variable(name, provider)
```

事件:`system-prompt/assemble`(waterfall)做有序组装;`system-prompt/change`(emit)
使派生请求缓存失效;在途请求保持其冻结 generation,新贡献只影响下一步,
新 `request/header` 记录 contributor 级 diff。

### 2. Durable runtime-context snapshots(时效事实不走 system prompt)

借 dsh time-context 的形态:时间敏感/情景性事实作为**带来源标记的 durable
`user/message`**(`kind: 'plugin'`、plugin 名、`form: 'snapshot'`、section 信息)进入会话
日志。精确的产出规则(dsh RuntimeContextProjection):**只在快照文本变化时**才产出新的
durable 消息(而非每步重复);快照被 replace 遮蔽(`sourceEventSeqs` 命中)即失效,
投影回到 null;空快照写固定文案而非缺席。理由(预研 §5.5.2):保持请求重建诚实、
prompt cache 稳定、注入内容在 trajectory 可见。初始运行时上下文贡献者:当前项目/章节
快照、当前任务/目标关联(架构 §14 清单第 8、9 项)。

### 3. Typed dynamic blocks 与不可信数据

- 所有动态 body 用 typed blocks,显式区分 instruction/data 并 escaping;
- 知识与手稿内容**始终是不可信数据**:只作 data block,永不升格为指令;
- prompt 插件只拿到有界快照,不获得数据库或文件系统服务;
- 完整 prompt 只持久化在私有请求快照,不进结构化日志。

### 4. 文件背书的 instructions 与 Writing Skills

- 精确文件监听(非目录扫描)、debounce、detached candidate 解析与校验,
  候选成功后发布新 contribution revision;无效编辑保留 last-good,
  诊断显示文件名安全的错误、失败阶段与重试动作;
- 激活边界是**下一步**:重载内容不影响在途 generation;
- Writing Skills:auto/explicit/none 选择、entrypoint 与 references、
  skill 选择/阅读屏障与引用上限(现 `src/main/skills/` 的 catalog/router/budget 语义
  原样保留,改造为 contribution + `read_writing_skill` 的 Main 权威)。

### 5. Context planner 与 immutable writing snapshot

- `writellm.writingContext`(Main):不可变有界写作快照;canonical section read 返回
  source snapshot ID,R6 的变更工具以它绑定变更资格(乐观版本);
- 自动有界上下文与精确模型上限:`agent-context-budget.ts`/`agent-model-limits.ts` 语义
  引擎中立化后由 context planner 消费;token 计量(`writellm.tokenMeter`)采用
  **usage 锚点优先**规则(dsh 同款):provider 上报 usage ≥ 启发式估算时采用 usage
  为基线,否则全量重估(启发式约 4 chars/token + 块/角色开销)——防止 provider
  少报导致上下文超界;
- **当前请求永不被递归截断**(compaction 只在连续完整 turn 边界 fold,R7 落地)。

### 6. 读工具与工具运行时(9 个)

`get_writing_context`、`read_outline`、`read_section`、`search_manuscript`、`search_knowledge`、
`read_citations`、`read_writing_skill`、`inspect_change`(只读形式)、`check_draft`。

- 全部经 `writellm.toolAuthority` 的类型化 Main RPC;worker 无数据库/路径;
- 工具运行时强制项(架构 §15,管线形态对齐 dsh):immutable 参数快照(lossless 物化
  + 冻结)、闭合 schema 与有界输出、来源模型请求授权、agent/session/run/call 身份、
  parallel/exclusive 显式分类(`isConcurrencySafe`,只有分类为安全的读工具可并行;
  同 step 多 call 按组调度,**结果按模型顺序提交**,不按完成序)、协作取消
  (abort 后未 dispatch 的 call 记合成 `tool/call`+`tool/result`,
  code `TOOL_ABORTED_BEFORE_DISPATCH`)、精确 call/result 持久化、
  纯 replay 呈现元数据;错误码表 `UNKNOWN_TOOL / INVALID_TOOL_OUTPUT / ABORTED /
  ABORTED_BEFORE_DISPATCH`;guard 单调收紧的顺序:全局先、scope 链由远及近、
  首个 deny reason 赢;
- `check_draft` 保持确定性(Main `draft-checker.ts` 语义),作用在不可变快照上;
- 提交顺序遵循架构 §9.4(durable call → pre-execute → execute/Main RPC →
  post-execute → durable result → live 通知)。

## 测试计划

- 每个读工具的合同测试:合法/非法/过时快照/超界/取消/未授权/provider 错误;
- prompt 装配:排序确定性、同名 shadow、exclusive 冲突、未解析变量、预算超限
  均在 provider I/O 前失败;
- reload:有效编辑推进 composition revision 且只影响下一步;无效编辑保留 last-good
  并报告失败阶段;在途请求逐字节不受影响;
- 每个结果在模型继续前已持久化且可重建;
- golden 场景比对产品事实(非 Pi 事件形状);只读 Agent E2E 在项目重开与
  worker 重启后通过;
- 合同测试证明:Cordis 在本阶段**不能**创建提案或变更产品状态。

## 验收门槛

- 上述测试全绿;引擎参数化 E2E 机制建立且只读场景双跑通过;
- 请求头含每个 prompt/context/tool contributor 的身份、revision、顺序与 hash;
- Pi 行为不变;Electron 全套与打包门通过。

## 回滚

禁用 Cordis 引擎选择。只读产品状态除自身会话日志与模型审计外无外部影响。

## 风险

| 风险 | 控制 |
| --- | --- |
| prompt 注入退化成通用 append hook | 五类贡献 + 注册契约 + 装配期失败;exclusive 强制落实在合同测试 |
| 时效事实污染 prompt cache/重建 | durable 来源标记消息 + 限流(不进入 system prompt) |
| 文件 watcher 重载撕裂在途请求 | detached candidate + last-good + next-step 激活;快速连改串行合并 |
| 读工具并行调度安全性 | parallel/exclusive 显式分类,未分类默认 exclusive |
| Skill 屏障被新装配绕过 | 选择/阅读屏障与引用上限进合同测试,与现状逐项对齐 |
