## 目标

移除真实用户在正常 WriteLLM Agent 工作中必须选择 Pi 的**所有剩余理由**。
前置:R3–R6 已验收。R7 是体量最大的阶段,内含一个独立的 provider 适配器工作流;
建议实施时把 provider 适配器矩阵与 UI 平价拆成两个并行子轨,各自有 gate。

## 设计细节

### 1. Provider 适配器矩阵(最高风险工作流)

现有 Agent  advertised 的协议族(`piApiSchema`,10 个):

```text
openai-completions | openai-responses | azure-openai-responses | openai-codex-responses
anthropic-messages | bedrock-converse-stream | google-generative-ai | google-vertex
mistral-conversations | pi-messages
```

规则(架构 §13):

- 每个协议一个 Cordis 适配器插件,注册进 `writellm.llm`;实现可用现有 AI SDK/provider 包
  或窄协议客户端,但**零 pi-ai 导入**(import-boundary 机械执行);
- 适配器不持有 provider 配置或凭证;凭证经平台 `credential-service` 的 request-scoped
  lease 发放,只送达受信任的 LLM adapter 调用点;
- 每个流在到达 loop 前归一化(消息/chunk/usage/tool-call delta/thinking);
  受控传输插件 `writellm.outboundHttp` 拥有 endpoint 校验、headers、abort、
  retry 分类与安全诊断;
- provider 切换在 step 边界生效,永不在在途请求内;
- 配置了不受支持的协议 → run 创建前失败,**永不静默回落 Pi**;
- `pi-messages`:用新的非 Pi 实现承接,或经单独的用户批准产品决策移除——二选一,
  不允许拖延成事实兼容;
- 每个适配器:focused stream/tool/usage/retry 测试 + 录制的流/错误/usage fixture;
  被授权的真实 provider smoke 另行授权。

能力钳制:provider/model/thinking 选择与 clamping 复用平台层
(`agent-model-limits.ts` 的语义引擎中立化),UI 选择器两引擎共用目录服务。

### 2. 会话运营平价

| 能力 | 现有参照 | Cordis 落地 |
| --- | --- | --- |
| 标题生成与 fallback | `session-title.ts`(88 行)+ service 方法 | 独立小插件;durable `session/title{title, messageSeqs, source}`(source 区分 fallback/provider/user,用户改名钉住不被自动覆盖);LLM 生成走窄调用:dispatch 前提交 durable 请求记录、输入 JSON 帧化防注入、deadline 超时;确定性 fallback 语义不变 |
| 队列 steer/follow-up/delete | `session-service.ts` 的 steer/followUp/pending 操作 | `writellm.inbox` per-agent 插件;splice **先 append durable `inbox/*` 事件、后改内存**(同步观察者看到 splice 前状态,可按坐标重建);**顺序在 provider 请求序上证明**,不只是 UI 序 |
| 自动/手动 compaction | `context-checkpoint.ts` + `context-planner.ts` + `agent-context-budget.ts` | `writellm.compaction` provider seam;**安全切点是无未应答 tool-call 的 surface cut**(provider 拒绝悬挂 call);durable `compaction/start|summary|end|prune` 事件族,prune 计量事件紧贴 replace 之前(shadow-price 协议);摘要请求重放最后路由请求的 system/tools/消息前缀以复用 provider cache;失败保留上一 checkpoint;永不截断当前用户请求;附带 model-free 的 tool-result pruner(head/tail 截中段) |
| task/step 关联与 Resume | runs 的 task FK + Resume 行为 | durable 事件关联;恢复由事件日志重建 |
| 消费屏障 | follow-up 的 consumption barrier | inbox consumed 事件先于下一步装配 |

### 3. 活动与注意力投影

- `projectActivitySnapshot`/attention 投影(现 `session-service.ts` + `event-broker.ts`
  + renderer `agent-view-model.ts` 943 行折叠逻辑)在 Cordis 侧作为**纯 replay 投影插件**
  重建:同一 durable 事实,独立只读投影,不与 chat 投影互改状态;
- active/paused/failed 状态语义与现有 `activityStatus` 对齐。

### 4. Renderer 平价(评审轮显式补强的范围)

- 提案评审与 change-set 批量 UI(现 `agent-proposal-actions.ts`、review workbench);
- live partial rendering、replay 分页、tool cards、error/retry、archive/restore;
- **composer UX 平价**(ADR 038–041):progressive disclosure、approval shorthand、
  circular send action、pending follow-up queue 展示与操作;
- **quick actions 平价**:目录、composer 插入行为(现 `quick-actions.ts` + 契约),
  E2E 与现行为一致;
- 设置:完整 Cordis Agent 设置(approval 模式、模型/thinking、skill 选择),
  会话级设置覆盖 app 级默认的语义与现状一致。

### 5. 诊断与可解释性(Harness 体验的核心交付)

- trusted 内置插件的 enable/disable/reconfigure 控件,每次操作显示 last-good 回滚状态
  (成功/失败阶段、当前生效 generation);
- plugin inventory:直接投影 live Loader/Fiber registry(不维护第二份生命周期真相),
  字段含稳定 entry ID、catalog/plugin ID 与版本、effective enablement、scope、
  composition/config revision、Fiber phase、required/provided services、
  上次激活/teardown 时长、上次 reload 结果;
- trajectory inspector:分页、虚拟化、搜索、折叠、streaming tail-follow;
  按 step 展示 request/header 相较前一 header 的 diff(分类
  `initial | system | tools | system-and-tools`,借 dsh ui-trajectory 的
  `reader.previous` 快照比对)、contributor 身份与 revision、
  provider/model、token 预算与用量、TTFT(自 snapshot commit ack 后的 provider dispatch
  起算)与 decoding、重试、工具嵌套、审批等待、Main IPC 与事务时长、中断与错误;
  事件→UI 节点走注册制管线(match/start/update/buildViewNode),新节点种类由插件
  贡献;只读投影,不能改会话状态;导出时显式披露。

### 6. 可访问性与平台行为

- 与产品要求一致的 accessibility、响应式布局、键盘行为(现有 `e2e/accessibility.spec.ts`
  覆盖扩展到 Cordis 面板)。

## 测试计划与 provider gate

- provider gate:每个仍 advertised 的协议有适配器与 focused 测试,否则协议在 run 创建前
  失败且 UI 标注不可用;协议移除只能经单独用户批准的产品决策;
- 队列顺序在 provider 请求序上证明(交错 steer/follow-up 的 property 测试);
- exact request reconstruction 跨 compaction 与 provider 切换通过;
- 20 个工具端到端零 legacy import(扫描证明);
- Electron 全套、全部恢复 fixture、全部 fresh Real-Electron 场景、accessibility、
  视觉检查、跨平台 package 门。

## 验收门槛

- §15 平价矩阵 21 行逐行签核(含 Composer UX 与 Quick actions);
- 真实用户工作流无理由选择 Pi(由 R8 的证据演练复核);
- 上述测试全绿。

## 回滚

默认引擎切回 Pi。Cordis 会话在引擎重新启用前保持独立可读。

## 风险

| 风险 | 控制 |
| --- | --- |
| provider 平价拖延,R8 被堵 | 适配器矩阵是 R7 的硬子 gate;`pi-messages` 二选一不拖延;每个协议独立的录制 fixture |
| UI 平价工作量被低估(现 agent-panel 4371 行 + view-model 943 行) | 引擎参数化 E2E 复用现有场景;composer/quick actions 单独列行,不隐含在"面板"里 |
| trajectory/inventory 做成第二份状态真相 | 只读投影 durable facts 与 live registry; invariant 测试证明投影可重建 |
| 长会话 UI 性能 | replay 分页 + 虚拟化是验收项,不是优化项 |
