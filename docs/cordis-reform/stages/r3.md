# R3 — Cordis 持久会话纵切

状态:设计稿
对应计划:`../implementation-plan.md` 第 7 节;`../target-architecture.md` 第 9、11.1 节
上游引用:dsh 的 session/loop 分层(预研 §5.3:durable SessionEvent log 与 live Cordis
event 分工;turn 轨迹 `turn/start → step/start → … → turn/end`;`request/header` 在模型
dispatch 前提交且请求对象冻结,messages 从 durable session 派生);cordis 框架行为以
r1.md 的 conformance 冻结为准

## 目标

打通最小但完整的真实链路:**创建 Cordis 会话 → 发送一条文本请求 → 流式收到一条
assistant 响应 → 重开项目 → 从项目本地持久化数据精确重建该请求**。全程不涉及任何
项目工具(读/写工具在 R5/R6)。前置:R1(基座)、R2(进程骨架与协议)已验收。

纵切的意义:用一条窄链路同时验证持久化模型、提交顺序、worker 副本、provider 适配、
Renderer 面板和 trajectory——这些之后不再返工,只在 R5–R7 上生长。

## 设计细节

### 1. Cordis 私有表(架构 §11.1,新增迁移)

| 表 | 职责 |
| --- | --- |
| `cordis_sessions` | 身份、标题、状态、schema/runtime 版本、设置、时间戳 |
| `cordis_events` | append-only 事件元数据 + 有界内联 payload/引用 |
| `cordis_payloads` | content-addressed 私有大体(content kind、hash、size、schema) |
| `cordis_request_snapshots` | 精确请求封套引用与指纹(SHA-256) |
| `cordis_session_projections` | 显式可重建的当前读模型 |
| `cordis_projection_cursors` | 可重建的投影进度 |

规则:

- 对 `agent_sessions`/`agent_runs`/`agent_events` **零外键**(import-boundary 含 SQL 扫描);
- 运行、turn、step、队列、压缩、消息以事件日志为权威;投影表只加速查询,
  恢复测试里删除并重建;
- Main 拥有全部写入:worker 提议事件,Main 分配 event ID、会话内单调序列号、
  提交时间戳、payload 引用与 hash、schema 版本;影响模型可见面或外部权威的事实,
  worker 在 Main 确认提交后才继续。

### 2. 提交顺序(不可协商)

```text
Main 提交 user input          -> 先于任何 provider 网络 I/O
Main 提交 request/header 快照 -> 先于任何 provider 网络 I/O
Main 提交 assistant/chunk     -> 先于 Renderer 发布
abort                         -> 产生 durable 终止 run 事件
```

- chunk 级提交允许物理批量/打包,但逻辑事件序、时间戳与精确重建必须无损;
- request snapshot 提交给每个模型请求增加一次 worker→Main→SQLite→ack 往返,
  已接受(桌面延迟量级);TTFT 自 ack 后的 provider dispatch 起算(架构 §19.1)。

### 3. `request/header` 快照内容(架构 §9.3)

网络 I/O 之前 Main 提交:精确有序 messages、精确组装 system prompt、精确模型可见
tool schemas、provider/model/protocol 选择、thinking/temperature/output/stop/context 限制、
context checkpoint 与源事件引用、**组装该请求的 worker composition revision** 与有序
prompt/context/tool contributor manifest、hash 与 schema 版本。大体内容进
`cordis_payloads`,`request/header` 引用不可变快照及其 SHA-256;凭证、授权头、
cookie、签名 URL、私有绝对路径永不持久化。

参照 dsh 的精确机制,并原样采用:

- 每个 step 以 session fold 出的上一 `request/header` 为种子,经 `agent/request`
  waterfall 提案本 step 请求;请求对象 `deepFreeze(structuredClone(...))` 冻结,
  `canonicalHeader` 归一(空 system/tools 变为 absent)后与上一 header 比较,
  决定追加 `request/header{reason: 'initial'|'resume'|'change'}`(无变化不追加);
- messages 从 durable session 派生(`deriveMessages`),不是单独的可变状态;
- invariant 插件(`llm/stream` 的 global+prepend listener)在每次真实 dispatch 前检查:
  请求已冻结、step/start 与 request/header 已落日志、
  `options.messages` 与 `session.deriveMessages()` **JSON 深等**、
  model/system/temperature/maxTokens/stop/tools 与 fold 出的 header 一致——
  这条 desync 防线是重建等价性的可执行证明,WriteLLM 原样引入。

### 4. Worker 侧插件

| 插件 | 职责 |
| --- | --- |
| `writellm.agentRegistry` | 创建/销毁 live Agent 实例与 agent scope(薄层;为 loop 可替换与测试 fake 而分离,不是多 agent) |
| `writellm.agentLoop` | 默认 turn/step loop 与 stopping 行为;dsh 参照:turn 可含多 step,step = 一次模型请求及其触发的工具执行(R3 无工具,恒单 step) |
| `writellm.sessions` | live session 对象与重建(remote-backed) |
| `writellm.sessionLog` | 经 Main 桥 append/replay 已提交 durable 事件 |
| 本地 session 副本 | `session/committed` 事件驱动的只读副本,供 prompt 装配派生 messages;**不是权威**,与 Main truth 的漂移由重建测试发现 |
| `writellm.systemPrompt` | 有序 prompt section 注册表与精确组装(R3 只有静态内置 section;贡献面在 R5 生长) |
| `writellm.llm` + token meter | provider-neutral prepared stream 调用与 token 计量 |
| `writellm.outboundHttp` / `writellm.providerLease` | 受控传输与 request-scoped 凭证 lease |

### 5. 首个生产 provider 适配器

- 至少一个真实协议适配器,零 Pi 导入(建议选当前产品默认 provider 所属协议族,
  使真实 smoke 可行;适配器契约见架构 §13 与 r7.md 第 1 节);
- 流在到达 loop 前归一化;usage 计量进 token meter 与模型审计。

### 6. Renderer 会话面板(最小可用,非平价)

- create/list/open/archive/restore/send/stop;
- 独立面板、独立缓存、独立 `cordis-agent:*` 订阅;与 Pi 面板零共享状态;
- live partial rendering 从 durable chunk 事件投影(先提交后发布,见上)。

### 7. Trajectory v1(只读)

- 按 step 展示:exact prompt 与 tool schema、contributor 列表及其变化、provider attempt、
  token usage、TTFT/decoding、durable commits、跨进程 correlation;
- 从 durable facts 重建,不引入第二份状态真相;本阶段无 span tree(架构 §19.1)。

### 8. 崩溃恢复

- Main 从 durable 日志把未闭合 run/step/turn 确定性收口,参照 dsh `repair.ts` 的
  `interruptedTurnClosers` 合成关闭序列:未配对的 tool/call 先补合成 `tool/result`
  (isError,code `TOOL_NOT_STARTED`/`TOOL_OUTCOME_UNKNOWN`,文案指导模型只重试
  只读/幂等操作)→ 补 `step/end` → 最后 `turn/end{reason:'interrupted'}`;
  合成事件的时间戳复用最后一个真实事件;`interrupted` 这个 turn 结束原因
  **只由崩溃修复写入**,正常路径永不产生;
- 模型请求遗留 running → 终结为 failed/interrupted,不重试外部活动;
- 投影表删除后从事件/payload 真相重建。

### 9. 事件信封与 surface 规则(借 dsh session 模型)

- 事件信封 `{type, seq, time, data, ignorable?}`:seq 会话内连续,append 时做
  lossless-JSON 校验与 deep-freeze,提交后才发 live `session/event`;
- 模型可见 transcript 由 surface 事件投影:`user/message`、`assistant/message`、
  `tool/result` 三型携带 `surfaceOp: 'append' | {op:'replace',start,end}` 与
  `sourceEventSeqs`;校验规则:seq 连续、replace 必须引用更早 seq 且含全部被遮蔽
  节点、**tool/result 的 replace 只允许改 content**(其余字段 JSON 深等)——
  compaction(R7)与 runtime-context 遮蔽都建立在这条规则上;
- `assistant/message` 在收齐时聚合本 step 的 chunk(`sourceEventSeqs` 引用 chunk seq)
  并携带 usage;空 content 的消息只承载 usage、不进 transcript;
- route(provider/model)变化时追加 `request/context` 事件;
- `turn/end` 的 reason 词表:`completed | aborted | blocked | error | max-tokens |
  interrupted`;
- agent scope 的事件过滤借 dsh-scope 的方向性:注册视图沿 scope 链向下继承,
  事件准入向上扩展(`scopeTarget` 携带祖先链 tag,事件永不向下流)。

## 测试计划

- **精确归一化请求重建测试**:重建结果与不可变 provider 请求逐字节等价;
  trajectory 能指认每个模型可见 contributor 与活跃 composition revision;
- 提交顺序测试:user input / request snapshot 先于网络 I/O(注入故障证明逆行失败);
- chunk 提交-发布顺序与批量打包的无损性;
- abort → durable 终止事件;崩溃恢复确定性收口;投影删除重建一致;
- Pi 会话对 Cordis 查询不可见,反之亦然;两引擎在同一项目可独立选择;
- 禁用/清空本地 trace 后请求与事件输出字节等价;
- 迁移备份/完整性/恢复;Electron 测试;fresh 与 resumed 会话 E2E;`check:package`。

## 验收门槛

- 上述测试全绿;
- 尚无工具或变更能力暴露(任何 tool 注册在 R3 装配中失败);
- Pi Agent 测试与 E2E 不改断言通过。

## 回滚

默认切回 Pi 并禁用 Cordis 会话创建。Cordis 表可惰性保留至前向清理迁移;
Pi 数据不受任何触碰。

| 风险 | 控制 |
| --- | --- |
| chunk 先提交后发布的吞吐瓶颈 | 物理批量打包允许;无损性测试;按现有 Pi 侧同路径实测对比 |
