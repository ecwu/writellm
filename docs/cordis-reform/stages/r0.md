# R0 — 接受并冻结架构

状态:设计稿
对应计划:`../implementation-plan.md` 第 4 节
上游引用:无外部依赖(纯决策阶段)

## 目标

在写入任何代码或依赖之前,完成三件事:

1. 审查并接受(或修订)[ADR 045](../../adrs/045-isolated-cordis-agent-replacement.md);
2. 冻结目标架构与分阶段计划,使其成为后续阶段的验收基准;
3. 把 R1 映射为一个新授权的项目 checkpoint,且只授权 R1。

R0 不改任何产品代码、依赖、迁移或打包配置。

## 工作项

### 1. ADR 045 审查清单

逐条确认以下内容,任一条不接受则回到文档修订:

- [ ] 十条固定约束(target-architecture 第 2 节)全部认可,特别是:
  双引擎可选、会话永不跨引擎、最终彻底删除 `@earendil-works/pi-agent-core` 与
  `@earendil-works/pi-ai`、不引入任意第三方/市场/模型生成代码插件面;
- [ ] 七个 rejected alternatives 的拒绝理由认可(含评审轮新增的"选择性复用 dsh 核心包");
- [ ] 范围决定认可:plan mode 与 subagent 排除并写入 non-goals;goal 与结构化提问
  (userQuestions)接受为 parity 之后的独立授权阶段,R1–R9 只预留接缝不实现;
- [ ] 后果清单认可,特别是:过渡期同时维护两套 Agent 实现与两套 Renderer 面板;
  Cordis 功能代码不得复用 Pi 运行时代码(即使照抄更快);
- [ ] 评审轮修订已落实:按进程划分的 composition 信任边界(Renderer 仅 core、
  生产配置禁用 `!!js`)、span trace 延期、R4 爆破半径标注、Host Protocol v1 轴心定位。

### 2. 目标架构与计划冻结

- [ ] `target-architecture.md` 状态从 proposed 改为 accepted(修订历史保留在 ADR);
- [ ] `implementation-plan.md` 的 R1–R9 阶段边界、全局规则 1–18、验收矩阵确认无误;
- [ ] 本目录(stages/)的 R1 细化稿评审通过,作为 R1 checkpoint 的实施依据;
- [ ] 确认后续阶段细化稿在对应阶段授权前逐个评审(R2 稿在 R1 验收前完成评审即可,
  不要求一次性全部审定)。

### 3. 明确 non-goals(写入架构文档 §3.2 与 ADR,已具备,此处为确认)

- 不做会话转换(Pi → Cordis);
- 不开放任意包加载、插件市场、动态代码执行;
- 不做 shell、通用文件系统、通用网络工具;
- 不做 plan mode、subagent;
- 代码级 module HMR 仅限开发构建,不进生产面。

### 4. 两个待决事项给出结论

- [ ] **Pi 表销毁需要最终单独确认**:推荐答案为"是"——R9 的破坏性迁移在执行前需要
  用户显式批准(ADR 045 已按此起草,此处拍板);
- [ ] **R4 排期自由度**:确认 R4(引擎中立产品权威)不依赖任何 Cordis 代码,
  允许独立排期、甚至先于 R1 交付;默认仍按 R3 之后执行,除非用户希望先消除
  产品表的 Pi 外键。

### 5. checkpoint 映射

- [ ] 在 `docs/implementation-todo.md` 与 `docs/current-plan.md` 中把 R1 登记为下一个
  授权 checkpoint,验收标准引用 `stages/r1.md` 的验收门槛;
- [ ] 确认 R2–R9 均未授权,每个阶段开工前需要单独的 checkpoint 授权。

## 验收门槛

- ADR 045 状态更新为 accepted;
- `docs/architecture.md`、`docs/current-plan.md`、tracker 条目、history 路由四处一致;
- 仓库无任何产品代码、依赖或迁移变更(`git diff --stat` 仅含 docs/);
- R1 细化稿(stages/r1.md)评审通过。

## 回滚

R0 只产生文档状态变化;撤销接受即回滚,无数据或代码影响。

## 风险与备注

- 最大的流程风险是"接受架构"被默认成"授权全部阶段"。R0 的输出必须逐阶段显式:
  接受 ADR ≠ 授权 R2–R9。
- 冻结不等于不可修订:后续阶段的实现证据若要求改架构,走 ADR 修订流程
  (先停、记录原因与替代、用户批准、更新文档,再实现)。
