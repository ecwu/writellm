# Feature Specification: PDF 资料导入与处理

**Feature Branch**: `006-source-library-processing`

**Created**: 2026-07-11

**Status**: Draft

**Input**: 从原 `001-ai-writing-workspace` 拆分：导入 PDF，保存解析产物，并管理资料处理状态。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 导入 PDF 资料 (Priority: P1)

作为作者，我希望把本地 PDF 导入项目资料库，以便后续查看和检索文献内容。

**Why this priority**: 资料必须先安全进入项目，后续检索和 AI 引用才有可靠来源。

**Independent Test**: 导入一份包含文字、图片和表格的 PDF，确认资料被保存并可查看处理状态。

**Acceptance Scenarios**:

1. **Given** 用户在资料库，**When** 用户选择一个 PDF，**Then** 系统创建资料记录并展示处理进度。
2. **Given** 用户选择非 PDF 文件，**When** 用户提交导入，**Then** 系统阻止导入并说明支持的格式。
3. **Given** 用户导入重复 PDF，**When** 系统发现可能重复，**Then** 系统让用户选择保留、替换或作为独立资料。

### User Story 2 - 查看解析和索引状态 (Priority: P1)

作为作者，我希望知道资料正在解析、切分、建立检索表示还是失败，以便判断它何时可以用于后续工作。

**Why this priority**: 未完成或不完整的资料不能被误认为可靠证据。

**Independent Test**: 观察一份正常 PDF、一份无文字 PDF 和一份处理失败 PDF，确认状态和原因均清晰可见。

**Acceptance Scenarios**:

1. **Given** PDF 正在处理，**When** 用户查看资料库，**Then** 系统显示当前阶段且不将其列为可引用资料。
2. **Given** PDF 处理完成，**When** 用户查看资料，**Then** 系统能查看解析后的 Markdown、图片和嵌入的表格。
3. **Given** 解析结果不完整或检索表示生成失败，**When** 处理结束，**Then** 系统保留资料和已完成产物，并显示部分失败或失败原因。

### Edge Cases

- PDF 无法读取、加密、损坏或没有可提取文字时，必须保留失败记录。
- 图片提取失败时，不能把缺失图片伪装成完整解析结果。
- 表格跨越文本处理边界时，必须保留足够的表头和上下文。
- 第三方解析服务超时或返回无法验证的结果时，资料不能进入可检索状态。
- 重新处理同一资料时，系统必须保留处理历史，并明确当前哪一份产物有效。

## Scope

### In Scope

- 本地 PDF 导入和资料元数据。
- PDF 到 Markdown、图片和 Markdown 表格的解析产物保存。
- 文本切分、检索表示生成和处理状态展示。
- 处理失败、部分失败和重试提示。

### Out of Scope

- 关键词或自然语言检索界面。
- 将资料片段插入章节作为引用。
- AI 写作任务和版本历史界面。
- 自行开发 PDF 解析引擎。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户向当前项目导入本地 PDF。
- **FR-002**: 系统 MUST 拒绝不支持的文件格式并说明原因。
- **FR-003**: 系统 MUST 为每份资料保存来源名称、原始文件和处理状态。
- **FR-004**: 系统 MUST 将可读取 PDF 解析为可查看的 Markdown，并保留图片与表格的正文关系。
- **FR-005**: 系统 MUST 将解析后的文本切分为可检索文本块。
- **FR-006**: 系统 MUST 为每个可检索文本块保存对应的检索表示和来源位置。
- **FR-007**: 系统 MUST 区分导入、解析、切分、检索表示生成、可用、部分失败和失败状态。
- **FR-008**: 只有同时具备文本、检索表示和来源位置的文本块才能进入可检索状态。
- **FR-009**: 处理失败时系统 MUST 保留资料和可用的部分产物，并显示失败原因和重试建议。
- **FR-010**: 系统 MUST 识别可能重复资料，并在覆盖或保留前取得用户选择。

### Key Entities

- **资料**：用户导入项目的 PDF 及其解析产物、来源信息和处理状态。
- **资料文本块**：从解析产物中切分出的文本单元，包含文本、位置和检索表示。
- **处理事件**：一次解析、切分、检索表示生成或重试的状态和结果记录。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少 95% 的 20 页以内可读取 PDF 能在 60 秒内显示“可检索”或明确失败原因。
- **SC-002**: 100% 显示为可检索的文本块同时具备文本、检索表示和来源位置。
- **SC-003**: 100% 的失败或部分失败资料都保留在资料库并显示处理原因。
- **SC-004**: 至少 90% 的作者能在 30 秒内判断一份资料是否可以用于检索。
- **SC-005**: 100% 的重复资料处理都不会静默覆盖原资料。

## Assumptions

- 本 feature 依赖 `001-project-foundation` 和 `002-workspace-shell` 提供项目资料库入口。
- 首版只处理本地 PDF；解析服务可由产品配置，但产品负责验证结果和展示状态。
- 图片不要求单独生成视觉检索表示，但必须保持与解析文本的位置关系。
- 搜索和引用由 `005-source-search-citations` 负责。
