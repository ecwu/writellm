# Feature Specification: PDF 资料导入与处理

**Feature Branch**: `006-source-library-processing`

**Created**: 2026-07-11

**Updated**: 2026-07-12

**Status**: Draft — refreshed against accepted 001 and 011; requires plan refresh and acceptance

**Input**: 让作者把本地 PDF 纳入当前项目资料库，理解每份资料的处理质量和可用状态，并在失败时保留来源与恢复路径。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 将 PDF 导入当前项目 (Priority: P1)

作为作者，我希望把本地 PDF 导入当前项目的资料库，以便集中管理后续写作可能使用的来源。

**Why this priority**: 资料必须先以可识别、不会静默覆盖的方式归属当前项目，后续阅读、搜索和引用才有可信来源。

**Independent Test**: 在一个已打开项目中导入 PDF，关闭并重新打开项目，确认资料记录、来源文件、显示名称和状态仍可识别。

**Acceptance Scenarios**:

1. **Given** 用户位于当前项目的资料库，**When** 用户选择可读取的 PDF，**Then** 系统创建资料记录、显示文件摘要并开始处理。
2. **Given** 用户选择不支持的文件，**When** 用户确认导入，**Then** 系统阻止导入并说明当前支持 PDF，不创建误导性的资料记录。
3. **Given** 所选 PDF 可能与已有资料重复，**When** 用户继续导入，**Then** 系统在改变已有资料前说明匹配依据，并让用户取消、保留为独立资料或替换已有资料。
4. **Given** 用户取消文件选择或导入失败，**When** 用户返回资料库，**Then** 现有资料保持不变，失败操作不显示为成功。

---

### User Story 2 - 判断资料何时可用于搜索和引用 (Priority: P1)

作为作者，我希望看到资料从导入到可用的清晰进度和质量状态，以便知道它是否已经适合搜索和引用。

**Why this priority**: 未完成、内容缺失或来源定位不可靠的资料不能被误认为完整证据。

**Independent Test**: 分别处理正常 PDF、扫描件、加密文件、损坏文件和仅部分内容可读的文件，确认每份资料的状态、限制和可用资格准确。

**Acceptance Scenarios**:

1. **Given** 资料仍在处理中，**When** 用户查看资料库，**Then** 系统显示进行中状态和当前可理解阶段，并明确其尚不可用于搜索或引用。
2. **Given** 资料内容和来源定位均处理完成，**When** 用户查看该资料，**Then** 系统显示“可用”，并允许用户预览可读内容及其与原 PDF 的位置关系。
3. **Given** 仅部分内容成功处理，**When** 处理结束，**Then** 系统显示“部分可用”、指出已知缺失，并只把满足完整资格的内容开放给后续搜索和引用。
4. **Given** 资料无法处理，**When** 用户查看结果，**Then** 系统保留资料记录和原始来源、显示脱敏失败原因，并提供适用的重试或移除操作。

---

### User Story 3 - 预览处理结果并安全重试 (Priority: P2)

作为作者，我希望预览处理后的正文、图片和表格上下文，并在结果不完整时重新处理，以便在使用资料前发现明显问题。

**Why this priority**: 作者需要直接判断处理结果是否忠实，而不能只依赖一个成功标签。

**Independent Test**: 打开包含正文、图片、表格和跨页内容的资料预览，触发一次重试，确认旧结果在新结果确认前不会被静默替换。

**Acceptance Scenarios**:

1. **Given** 资料具有可预览内容，**When** 用户打开详情，**Then** 系统以可读顺序展示正文，并保留相关图片、表格、页码或其他来源位置上下文。
2. **Given** 图片、表格或部分页面缺失，**When** 用户查看预览，**Then** 系统明确标识缺失或不确定范围，不把残缺结果展示为完整。
3. **Given** 用户对失败或部分可用资料发起重试，**When** 新处理尚未完成，**Then** 系统保持现有可用结果和来源可识别，并明确显示重试进行中。
4. **Given** 重试完成，**When** 用户查看资料，**Then** 系统明确显示当前有效结果及其完成时间；失败的重试不得破坏先前可用结果。

### Edge Cases

- PDF 加密、损坏、权限不足、无可读文字或仅包含扫描图像时，系统必须说明限制，不能伪装为完整可用。
- 文件很大、处理时间较长、应用关闭或项目暂时不可用时，重新打开后不得把未确认结果显示为完成。
- 图片或表格与正文关联不确定时，系统必须标识不确定性，不得创建虚假上下文。
- 跨页表格、脚注、多栏布局或页码缺失时，预览必须保留可理解的阅读和来源定位线索，或明确说明无法可靠定位。
- 替换资料时，系统必须在确认前说明对已有搜索资格和引用的影响；不得静默修改正文引用。
- 在窄窗口、200% 文本缩放、键盘操作、明暗主题和减少动态效果条件下，状态、预览、重试与移除操作必须保持可达。

## Scope

### In Scope

- 向当前项目导入本地 PDF，并显示名称、文件摘要、导入时间和处理状态。
- 生成供作者预览以及后续搜索和引用使用的可读内容与来源定位信息。
- 展示正文、图片、表格和来源位置之间的可理解关系。
- 进行中、可用、部分可用、失败和重试状态，以及脱敏原因和恢复操作。
- 重复资料识别以及由用户确认的保留、替换或取消流程。

### Out of Scope

- 搜索界面、结果排序、筛选和正文引用插入。
- AI 写作任务、提案生成和版本历史。
- 对导入资料进行内容改写、翻译、总结或事实核查。
- 保证所有 PDF 版式、扫描质量或受保护文件都能完整恢复。
- 自动判断资料的学术质量、版权许可或引用适用性。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户把本地 PDF 导入当前已打开项目的资料库，并显示可识别的资料摘要和导入结果。
- **FR-002**: 系统 MUST 拒绝不支持、不可访问或无法确认的文件，说明原因，并 MUST NOT 将失败操作显示为成功导入。
- **FR-003**: 每份资料 MUST 保留其原始来源、用户可见名称、导入时间、当前处理状态和当前结果完成时间，以便关闭并重新打开项目后仍可识别。
- **FR-004**: 系统 MUST 让用户区分等待处理、处理中、可用、部分可用、失败和重试中状态，并通过文字说明当前资料能否用于后续搜索和引用。
- **FR-005**: 资料只有在可读内容及其原始来源定位均可用时，相关内容才 MUST 被标记为可供后续搜索和引用。
- **FR-006**: 系统 MUST 提供处理结果预览，使用户能够阅读正文，并在存在时查看相关图片、表格、页码或其他来源上下文。
- **FR-007**: 内容、图片、表格或来源定位缺失或不确定时，系统 MUST 标识受影响范围，并 MUST NOT 把部分结果表示为完整结果。
- **FR-008**: 处理失败时，系统 MUST 保留资料记录和原始来源，显示不含敏感路径或原始异常的失败摘要，并提供适用的重试或移除操作。
- **FR-009**: 用户 MUST 能够重试失败或部分可用资料；重试期间先前可用结果 MUST 保持可识别，失败重试 MUST NOT 破坏先前可用结果。
- **FR-010**: 系统 MUST 识别可能重复的资料，并在替换已有资料前取得用户确认；取消或保留为独立资料 MUST 不改变原资料。
- **FR-011**: 替换或移除可能已被使用的资料前，系统 MUST 向用户说明对可搜索状态和现有引用的影响，并 MUST NOT 静默修改章节正文。
- **FR-012**: 资料库状态、预览、错误、确认和操作 MUST 沿用 011 定义的主题、排版、键盘、焦点、非颜色状态和受控共享交互规则。

### Key Entities

- **资料**：归属于当前项目的原始 PDF、用户可见摘要、导入时间和当前处理资格。
- **处理结果**：供作者阅读以及后续搜索和引用使用的内容、相关媒体、来源定位、完整性说明和完成时间。
- **处理状态**：资料的等待、进行中、可用、部分可用、失败或重试中结果，以及用户可采取的下一步操作。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对基准集中所有受支持且可读取的 20 页以内 PDF，至少 95% 在 60 秒内显示“可用”“部分可用”或明确失败结果；该指标不要求所有文件成功处理。
- **SC-002**: 100% 显示为可供搜索和引用的内容同时具有可读内容与可回到原 PDF 的来源定位。
- **SC-003**: 在正常、扫描、加密、损坏、无文字、图片缺失和表格缺失测试中，100% 的资料显示与实际完整性一致的状态，不把已知残缺结果表示为完整。
- **SC-004**: 100% 的失败或部分可用资料保留原始来源和可理解的原因，并提供至少一种安全退出路径；适用时提供重试。
- **SC-005** *(post-launch outcome; non-blocking for implementation acceptance)*: 后续可用性测试中，至少 90% 的作者能在 30 秒内正确判断一份资料是否可用于搜索和引用。
- **SC-006**: 100% 的重复、替换、取消和失败重试测试不会静默覆盖原资料、破坏先前可用结果或修改章节正文。
- **SC-007**: 在仅键盘、System/Light/Dark、减少动态效果、960×640 和 200% 文本缩放条件下，100% 的状态、预览、确认和恢复操作可达。

## Assumptions

- 001 已提供可移动项目及其身份边界，002 将提供项目内资料库槽位，011 已定义后续界面共同使用的视觉与交互基础。
- 首版面向单作者、单机项目，并只接受用户主动选择的本地 PDF。
- 处理结果属于当前项目内容；项目移动后，资料和其可见状态仍随同一项目保持可识别。
- 007 只消费本 feature 明确标记为可用的内容和来源定位；本 feature 不定义搜索排序或引用体验。
