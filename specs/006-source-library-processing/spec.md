# Feature Specification: PDF 知识库摄取与索引

**Feature Branch**: `006-source-library-processing`

**Created**: 2026-07-11

**Updated**: 2026-07-12

**Status**: Draft — expanded to define durable background ingestion and indexing; requires clarification, plan refresh, and acceptance

**Input**: 作者批量导入 PDF 后，系统在后台按外部服务限额逐份解析并持久保存结构化 Markdown、图片和稳定内容块，再为内容块生成持久向量索引，使后续检索能用资料身份和内容块身份准确定位原文。

## Clarifications

### Session 2026-07-13

- Q: 内容块 embedding 使用本地模型还是第三方服务？ → A: 不使用本地模型；使用用户自行配置的硅基流动 API，并固定调用 `BAAI/bge-m3`。

### Session 2026-07-12

- Q: 尚未实现的 feature 005 是否继续作为 006 的硬依赖？ → A: 否；006 移除对 005 的硬依赖，自行提供窄范围 MinerU 凭据配置并由 ADR-005 管理，不消费或修改 005 的 OpenAI-compatible provider contract。
- Q: MinerU 凭据、PDF 数据出境和 embedding 服务是否需要独立架构决策？ → A: 需要；新建并接受 ADR-005，独立记录 006 的用户自备凭据、第三方网络请求、数据出境和进程安全边界，不扩写 ADR-004。
- Q: MinerU 的数据保留、删除、驻留、子处理商和训练用途未知时，是否阻止功能进入实现？ → A: 不阻止；MinerU API 凭据由用户自行配置，用户选择配置并使用即表示接受该第三方服务条款，产品不提供该 API，也不承诺远端数据删除或处理政策。
- Q: 如何判定重复 PDF？ → A: 先以文件名和大小筛查并警告，再计算内容指纹；指纹相同即判定重复且不建立索引。
- Q: 首版是否必须支持扫描型 PDF 的 OCR？ → A: 使用 MinerU 完成 OCR 与解析，并接收其 Markdown、切块图片及块位置元数据产出。
- Q: 内容块的最小来源定位精度是什么？ → A: 由 MinerU 产出决定；保留块顺序和服务提供的元数据，但不要求回溯原 PDF。
- Q: “替换已有资料”应如何处理资料身份？ → A: 不支持替换；用户只能删除资料。
- Q: 移除已被后续引用使用的资料后，应保留什么？ → A: 只要资料存在引用，就禁止删除。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 批量导入资料并立即离开 (Priority: P1)

作为作者，我希望一次选择多份 PDF 加入当前项目的知识库，并在导入后继续写作或关闭应用，以便资料处理不阻塞我的工作。

**Why this priority**: 可靠创建资料与后台任务是整个知识库构建流程的入口；没有持久队列，长时间解析和索引无法安全完成。

**Independent Test**: 在一个已打开项目中一次导入多份 PDF，确认每份资料立即获得独立记录和排队状态；关闭并重新打开应用后，确认未完成任务仍可恢复且不会重复创建资料。

**Acceptance Scenarios**:

1. **Given** 用户位于当前项目的资料库，**When** 用户选择一份或多份可读取 PDF，**Then** 系统为每份文件创建独立资料记录、保存其原始来源并加入后台处理队列。
2. **Given** 一批文件中同时存在有效 PDF、不支持文件和不可读取文件，**When** 导入完成，**Then** 系统逐项报告结果，只为可接受文件创建资料，不因单个失败丢弃整批有效文件。
3. **Given** 多份资料正在排队或处理，**When** 用户继续使用应用，**Then** 前台写作保持可用，资料库显示每份资料的阶段和结果。
4. **Given** 应用在任务完成前关闭，**When** 用户重新打开同一项目，**Then** 系统恢复未完成任务或将其置于可恢复状态，已完成工作不被重复计算或误报为丢失。
5. **Given** 所选 PDF 的文件名和大小与已有资料相同，**When** 系统完成内容指纹计算，**Then** 系统提示初步匹配；若指纹相同则将其标记为重复、不创建索引工作，并允许用户取消该项导入。

### User Story 2 - 获得有序的结构化资料 (Priority: P1)

作为作者，我希望系统把每份 PDF 转换为可读、可预览且顺序稳定的结构化内容，以便我确信知识库没有把正文、图片或表格上下文混淆。

**Why this priority**: 后续索引和引用必须建立在稳定、可验证的内容身份、块顺序与解析元数据之上。

**Independent Test**: 使用 MinerU 处理包含正文、标题、图片、表格、跨页内容和扫描页的 PDF，确认结果按阅读顺序显示，且任一合格内容块都能通过资料身份与内容块身份稳定找回相同内容、关联图片及 MinerU 提供的元数据。

**Acceptance Scenarios**:

1. **Given** MinerU 返回结构化 Markdown、切块图片和块元数据，**When** 系统接受该结果，**Then** 系统保存可读内容、相关图片或表格、阅读顺序、内容块身份及服务提供的位置元数据。
2. **Given** 用户打开已解析资料，**When** 用户预览处理结果，**Then** 用户能按顺序阅读结构化内容，并理解正文、图片和表格之间的关系。
3. **Given** 一个内容块已成功保存，**When** 系统或后续功能以资料身份和内容块身份查找它，**Then** 返回同一段内容、关联媒体、块顺序和 MinerU 提供的元数据，不依赖显示名称或队列顺序。
4. **Given** 解析结果缺少媒体、正文或必要的结构关系，**When** 处理结束，**Then** 系统标识受影响范围，只将满足完整资格的内容块开放给后续索引与检索。
5. **Given** 外部结果格式错误、身份重复或引用不存在的媒体，**When** 系统验证结果，**Then** 系统拒绝不一致部分并显示可恢复失败，不把未经验证的数据标记为可用。

### User Story 3 - 在后台完成内容块索引 (Priority: P1)

作为作者，我希望已解析内容自动逐块建立检索索引，以便无需手动操作就能让资料逐步具备后续搜索资格。

**Why this priority**: 结构化内容只有完成可持久恢复的索引后，才能稳定支持 007 的语义检索。

**Independent Test**: 导入一份包含多个内容块的资料，控制部分索引任务成功、限流、暂时失败和永久失败，确认合格块可并行推进、结果逐块保存、重启后只续跑未完成工作。

**Acceptance Scenarios**:

1. **Given** 一份资料包含多个可索引内容块，**When** 解析完成，**Then** 系统自动为每个合格内容块创建索引工作，并允许互不依赖的内容块并行推进。
2. **Given** 部分内容块已完成索引而其他块仍在等待，**When** 用户查看资料状态，**Then** 系统显示可理解的总体进度和部分可用范围，已完成结果立即持久保存。
3. **Given** 外部服务要求降低请求速度或暂时拒绝请求，**When** 后台工作遇到该限制，**Then** 系统延后并安全重试合适的工作，不丢失队列、不制造重复有效结果，也不持续超出已知限制。
4. **Given** 应用在部分内容块完成后关闭，**When** 同一项目再次打开，**Then** 系统保留已完成索引，只恢复尚未完成或允许重试的内容块。
5. **Given** 某个内容块永久无法建立索引，**When** 其他内容块成功完成，**Then** 系统把资料显示为部分可用并明确失败范围，不阻止合格内容块供后续检索使用。

### User Story 4 - 理解进度并安全恢复 (Priority: P2)

作为作者，我希望看到每份资料处于排队、解析、索引、可用、部分可用或失败中的哪个阶段，并能安全重试或移除，以便长时间后台工作始终可理解、可控制。

**Why this priority**: 外部处理可能持续较久并发生限流、断网或部分失败，用户需要可信状态而不是一个模糊的加载指示。

**Independent Test**: 对排队、解析失败、部分索引失败、重试中和完成资料分别执行查看、重试与移除，确认状态准确，失败重试不破坏已有结果。

**Acceptance Scenarios**:

1. **Given** 资料正在排队或处理，**When** 用户查看资料库，**Then** 系统显示当前阶段、可理解进度及其当前是否可供搜索。
2. **Given** 资料处理失败或部分失败，**When** 用户查看详情，**Then** 系统显示不泄露敏感信息的原因、受影响范围及适用的重试或移除操作。
3. **Given** 用户发起重试，**When** 新工作尚未完成或再次失败，**Then** 先前有效的解析与索引结果保持可识别且不被破坏。
4. **Given** 用户移除一份仍在处理且未被引用的资料，**When** 用户确认影响，**Then** 后续后台工作停止采用该资料，新产生的结果不得使已移除资料重新出现。
5. **Given** 一份资料已被正文引用，**When** 用户尝试移除，**Then** 系统阻止删除并说明存在引用。

### Edge Cases

- PDF 加密、损坏、权限不足或超出 MinerU 接受范围时，系统必须说明限制，不能伪装为完整可用；扫描型 PDF 交由 MinerU OCR，无法识别的范围必须明确标识。
- 批量导入含同名文件、相同内容、部分重复文件或导入期间文件发生变化时，不得静默覆盖已有资料。
- 外部解析返回重复内容块身份、缺失身份、乱序结构、空内容、失效媒体引用或超大结果时，系统不得持久化为合格结果。
- 内容块为空、仅含无意义空白、只包含媒体或过大而无法建立索引时，系统必须保留可理解状态并避免产生误导性检索资格。
- 网络离线、认证失败、限流、超时、响应损坏或服务长期不可用时，队列必须保持可恢复，且不能无限快速重试。
- 项目被关闭、移动、重命名或暂时不可用时，后台工作不得写入错误项目；重新打开后必须核对项目与资料身份。
- 用户在处理期间移除未被引用的资料时，旧任务的迟到结果不得复活已移除资料。
- 在窄窗口、200% 文本缩放、键盘操作、明暗主题和减少动态效果条件下，状态、预览、重试与移除操作必须保持可达。

## Scope

### In Scope

- 向当前项目批量导入本地 PDF，持久保存原始资料并创建可跨重启恢复的后台工作。
- 按 MinerU 处理容量逐份完成 OCR 与解析，保存结构化 Markdown、切块图片、表格、阅读顺序和服务提供的块元数据。
- 为每份资料及其内容块建立稳定身份，使资料身份与内容块身份能够唯一找回内容、关联媒体、块顺序和 MinerU 元数据。
- 为合格内容块自动建立并持久保存语义检索所需的索引表示，支持块级并行、进度、限流、重试和部分完成。
- 展示资料及内容块的排队、处理中、可用、部分可用、失败和重试状态，以及预览和恢复操作。
- 以文件名和大小初筛、以内容指纹确认重复；确认重复的资料不建立索引。
- 删除未被引用的资料；存在引用的资料禁止删除。

### Out of Scope

- 搜索界面、查询理解、结果排序、筛选和正文引用插入；这些属于 007。
- AI 写作任务、提案生成和版本历史。
- 对导入资料进行内容改写、翻译、总结、事实核查或学术质量判断。
- 用户手工编辑解析后的结构化内容或内容块边界。
- 训练或微调解析模型、索引模型，或保证所有 PDF 版式和扫描质量都能完整恢复。
- 跨项目共享知识库、互联网资料抓取或项目外的全局索引。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户一次向当前已打开项目导入一份或多份本地 PDF，并逐项显示导入结果。
- **FR-002**: 对每份成功导入的 PDF，系统 MUST 创建独立且稳定的资料身份，持久保存原始来源、用户可见名称、导入时间、版本及处理状态。
- **FR-003**: 系统 MUST 将每份新资料加入持久后台工作队列，使前台使用不必等待解析或索引完成。
- **FR-004**: 系统 MUST 按已知 MinerU 处理容量调度 OCR 与解析工作；遇到限流或暂时故障时 MUST 延后合适的工作，并避免无界或立即重复请求。
- **FR-005**: 成功解析的资料 MUST 保存 MinerU 产出的结构化 Markdown、阅读顺序、切块图片或表格，以及服务提供的块元数据；系统不要求这些元数据支持回溯原 PDF。
- **FR-006**: 每个接受的内容块 MUST 具有在所属资料内稳定且唯一的身份；使用资料身份与内容块身份 MUST 能找回该块的当前内容、关联媒体、块顺序、服务元数据和处理资格。
- **FR-007**: 系统 MUST 在保存 MinerU 结果前验证资料归属、内容块身份、结构关系和媒体引用；不一致结果 MUST NOT 被标记为可用。
- **FR-008**: 系统 MUST 自动为每个具备可读内容和有效结构关系的非重复内容块创建索引工作，并 MUST NOT 为不合格或重复资料的内容块授予检索资格。
- **FR-009**: 互不依赖的内容块索引工作 MUST 能够并行推进，同时遵守当前已知服务限制；单个内容块失败 MUST NOT 阻塞其他合格内容块。
- **FR-010**: 每个内容块的索引结果、索引状态和结果版本 MUST 在完成后持久保存，并与对应资料版本和内容块身份关联。
- **FR-011**: 只有当前资料版本中同时具备可读内容、有效结构关系和有效索引结果的内容块，才 MUST 被标记为可供 007 检索。
- **FR-012**: 关闭并重新打开应用或项目后，系统 MUST 保留已完成结果，并恢复未完成或可重试工作，且 MUST NOT 重复创建已确认有效的结果。
- **FR-013**: 系统 MUST 让用户区分等待、解析、索引、可用、部分可用、失败和重试状态，并显示可理解的资料级进度与当前检索资格。
- **FR-014**: 解析或索引部分失败时，系统 MUST 保存仍有效的结果、标识受影响内容块，并允许其他合格块保持可用。
- **FR-015**: 用户 MUST 能够重试失败或部分可用资料；重试 MUST 保留先前有效结果，且迟到或旧版本结果 MUST NOT 覆盖当前资料版本。
- **FR-016**: 系统 MUST 先以文件名和文件大小筛查并提示可能重复，再为候选文件计算内容指纹；指纹相同时 MUST 将文件判定为重复、停止该项导入且 MUST NOT 创建索引工作。首版不支持保留重复副本或替换已有资料。
- **FR-017**: 系统 MUST 在删除资料前检查现有引用；存在任何引用时 MUST 阻止删除并说明原因。删除未被引用的资料前 MUST 说明对未完成工作和可搜索内容的影响，且 MUST NOT 静默修改章节正文。
- **FR-018**: 处理失败时，系统 MUST 保留资料记录和原始来源，显示不含凭据、敏感路径或原始异常的失败摘要，并提供适用的重试或移除操作。
- **FR-019**: 资料库状态、预览、错误、确认和操作 MUST 沿用 011 定义的主题、排版、键盘、焦点、非颜色状态和受控共享交互规则。
- **FR-020**: MinerU API 凭据 MUST 由用户自行配置；系统 MUST 保护凭据且不得在项目、日志或错误中泄露，并 MUST 将 PDF 仅发送至该凭据所配置的 MinerU 服务。配置并使用该凭据视为用户选择使用对应第三方服务；系统不负责验证或承诺该服务的数据保留、删除、驻留、子处理商或训练政策。
- **FR-021**: 内容块 embedding MUST 使用用户自行配置的硅基流动 API，并固定调用 `BAAI/bge-m3`；系统 MUST 保护该凭据，不得将凭据写入项目、日志或错误，并仅发送建立索引所需的合格内容块文本。

### Key Entities

- **资料**：归属于当前项目的一份原始 PDF，具有稳定身份、用户可见摘要、导入信息、当前版本和总体处理资格。
- **资料版本**：一次特定原始内容及其派生结果的边界；重新处理时用于防止旧任务结果覆盖当前内容，首版不支持以新文件替换资料。
- **内容块**：资料版本中的一个有序结构单元，具有资料内稳定身份、可读内容、关联媒体、块顺序、MinerU 元数据和检索资格。
- **媒体资源**：从资料获得并与一个或多个内容块相关联的图片或表格资源，保留来源与完整性状态。
- **处理任务**：解析一份资料或索引一个内容块的持久工作单元，记录阶段、尝试、进度、结果和可重试性。
- **索引结果**：与特定资料版本和内容块绑定、供后续语义检索消费的持久表示及其有效性状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户一次选择 100 份有效 PDF 后，100% 的文件在 10 秒内各自显示已导入、明确拒绝或可理解失败结果；后台处理不计入该时间。
- **SC-002**: 在应用于处理期间关闭并重新打开的测试中，100% 已完成的资料和内容块结果得到保留，100% 未完成工作恢复或显示明确可恢复状态，且不存在重复有效结果。
- **SC-003**: 对基准集中成功解析的资料，100% 被标记为可检索的内容块都能通过资料身份与内容块身份找回相同内容、关联媒体、块顺序及 MinerU 提供的元数据。
- **SC-004**: 在限流、断网、超时、认证失败和损坏响应测试中，100% 的任务进入准确且可恢复的状态，不丢失队列、不泄露敏感信息，也不把失败表示为成功。
- **SC-005**: 对包含至少 500 个合格内容块的基准资料，至少 95% 的内容块能在不阻塞前台写作的情况下完成索引；个别永久失败被准确标识且不阻塞其他块。
- **SC-006**: 在部分解析或部分索引失败测试中，100% 的合格内容块保持可识别，100% 的不合格内容块不会获得检索资格。
- **SC-007**: 在重复导入、资料删除、重试和迟到结果测试中，100% 的重复资料不建立索引，100% 被引用资料的删除被阻止，且旧任务结果不会复活已移除资料或静默修改章节正文。
- **SC-008** *(post-launch outcome; non-blocking for implementation acceptance)*: 后续可用性测试中，至少 90% 的作者能在 30 秒内判断一份资料当前处于哪个处理阶段、哪些内容可检索以及失败后可采取什么操作。
- **SC-009**: 在仅键盘、System/Light/Dark、减少动态效果、960×640 和 200% 文本缩放条件下，100% 的状态、预览、确认和恢复操作可达。

## Assumptions

- 001 已提供可移动项目及其身份边界，002 提供项目内资料库槽位，011 已定义界面共同使用的视觉与交互基础。006 不依赖 005；它自行提供窄范围 MinerU 凭据配置，并由 ADR-005 约束其安全边界。
- 首版面向单作者、单机项目，并只接受用户主动选择的本地 PDF；知识库及其派生内容随项目持久保存。
- 首版使用 MinerU 完成 PDF OCR 与解析，并消费其结构化 Markdown、切块图片和块位置元数据；MinerU 的接口契约、数据出境范围、限额和失败语义必须在计划阶段依据用户提供的文档调研并接受。语义索引能力仍须在计划阶段确定。
- MinerU API 由用户自行取得和配置，产品不提供共享凭据。用户配置并使用该凭据即选择接受 MinerU 的第三方服务政策；其数据保留、删除、驻留、子处理商和训练用途不构成本 feature 的验收门禁，产品亦不对远端处理作额外承诺。
- 006 的 MinerU 与硅基流动凭据、第三方网络请求和数据出境由独立 ADR-005 约束；不得通过扩写 ADR-004 改变 005 已接受的 provider contract。
- 语义索引固定使用硅基流动提供的 `BAAI/bge-m3`，不捆绑或执行本地 embedding 模型。硅基流动 API 由用户自行取得和配置，产品不提供共享凭据。
- 文档解析以资料为调度单位并服从服务容量；内容块索引可并行，但同样必须服从服务容量和安全重试规则。
- 外部服务可能不可用或只能处理部分资料，因此“部分可用”是首版受支持的正常结果，而不是必须回滚整份资料的异常。
- 007 只消费本 feature 明确标记为可检索的内容块及其稳定身份、可读内容、块顺序和 MinerU 元数据；本 feature 不定义查询、排序或引用体验。
