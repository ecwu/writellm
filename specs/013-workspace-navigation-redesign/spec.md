# Feature Specification: 分栏式工作区导航重构

**Feature Branch**: `013-workspace-navigation-redesign`

**Created**: 2026-07-13

**Status**: Accepted — maintainer accepted 2026-07-13

**Input**: 基于参考侧栏设计重新组织当前 UI：最左侧以 Sections、Knowledge Base 等一级类别切换工作上下文；中间侧栏列出当前类别的条目及摘要；主窗口显示所选 Section 或资料的内容与状态；设置使用独立入口集中管理 LLM、API、MinerU 等应用全局配置；AI agent 对话不放入本次左侧栏，留待后续规划。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从统一侧栏浏览 Sections (Priority: P1)

作为作者，我希望从稳定的一级导航进入 Sections，并在相邻列表中看到文章的所有 Section 及其意图摘要，以便快速理解文章结构并打开需要继续处理的部分。

**Why this priority**: Sections 是作者进入项目后最核心、最高频的写作导航；新的信息架构首先必须让文章结构比当前界面更容易扫描和切换。

**Independent Test**: 打开一个包含多个大纲条目和章节的项目，只使用新的一级导航与 Section 列表，确认作者能识别各项标题、摘要和状态，并在主区域打开任一对应内容。

**Acceptance Scenarios**:

1. **Given** 当前项目包含多个大纲条目，**When** 作者选择 Sections 类别，**Then** 相邻列表按既有大纲顺序显示所有条目，并为每项呈现标题、可用摘要和写作状态。
2. **Given** 一个大纲条目已有对应章节，**When** 作者选择该项，**Then** 主区域显示该章节的当前内容和所属 Section 上下文。
3. **Given** 一个大纲条目尚无对应章节，**When** 作者选择该项，**Then** 主区域显示该 Section 的规划信息和明确的下一步，而不伪造章节正文。
4. **Given** 作者正在查看一个 Section，**When** 切换到另一个 Section 后再返回，**Then** 两个 Section 的内容和既有保存状态均保持正确，导航本身不提交或丢弃编辑。
5. **Given** 当前项目没有大纲条目，**When** 作者进入 Sections，**Then** 列表和主区域共同显示可理解的空状态与创建首个条目的入口。

---

### User Story 2 - 浏览知识库资料与处理状态 (Priority: P1)

作为作者，我希望从 Knowledge Base 类别看到已导入、正在处理和需要处理的全部资料，并在主区域查看所选资料的内容、内容块与索引情况，以便判断哪些资料已经可用于后续写作。

**Why this priority**: 资料导入只有在处理进度、内容和检索资格可见时才真正可用；把资料列表和详情放进一致的导航结构是本次重构的另一项核心价值。

**Independent Test**: 准备分别处于等待、解析、索引、部分可用、可用和失败状态的 PDF，进入 Knowledge Base 后逐项打开，确认列表摘要与主区域详情准确对应且可执行动作来自现有资料能力。

**Acceptance Scenarios**:

1. **Given** 当前项目包含多份资料，**When** 作者选择 Knowledge Base 类别，**Then** 相邻列表显示当前项目的全部资料，包括等待处理、处理中、部分可用、可用、失败和可重试项目。
2. **Given** 作者在资料列表中选择一份已导入 PDF，**When** 详情加载完成，**Then** 主区域显示可读的资料预览、资料级处理状态、内容块总数、已建立索引的块数和当前检索资格。
3. **Given** 所选资料已有结构化 Markdown 结果，**When** 作者选择查看处理后内容，**Then** 主区域显示与该资料版本对应的 Markdown 内容，并清楚区别于原始 PDF 预览。
4. **Given** 所选资料仍在处理或只有部分结果，**When** 作者查看详情，**Then** 已完成内容保持可见，未完成范围、当前阶段和可检索范围得到明确说明。
5. **Given** 所选资料处理失败或可重试，**When** 作者查看详情，**Then** 主区域显示安全的原因摘要及现有资料能力允许的重试或移除操作，不泄露凭据、敏感路径或原始异常。
6. **Given** 当前项目没有资料，**When** 作者进入 Knowledge Base，**Then** 列表和主区域显示资料库空状态与导入 PDF 的明确入口。

---

### User Story 3 - 在主工作区间稳定切换 (Priority: P1)

作为作者，我希望一级类别、条目列表和主内容区形成稳定、可预测的分栏工作区，以便切换 Section 或资料时始终知道自己在哪里，同时不丢失当前工作上下文。

**Why this priority**: 本次需求的核心不是单独增加两个页面，而是建立可扩展、清晰且不会重置主内容的导航模型。

**Independent Test**: 在 Sections 和 Knowledge Base 之间反复切换，改变列表选中项、滚动位置和主区域内容状态，确认界面始终只有一个明确类别和一个明确详情上下文，且切换不会造成数据副作用。

**Acceptance Scenarios**:

1. **Given** 作者位于项目工作区，**When** 查看界面，**Then** 系统清楚区分一级类别栏、当前类别列表栏和主内容区，并标识当前类别与当前条目。
2. **Given** 作者从 Sections 切换到 Knowledge Base，**When** 切换完成，**Then** 列表栏改为资料列表，主区域显示该类别的默认内容或当前选中资料，不保留与当前类别不符的 Section 详情。
3. **Given** 作者随后返回 Sections，**When** 类别恢复，**Then** 系统恢复本次工作会话中最近选择的 Section；若该项已不存在，则使用安全默认项或空状态。
4. **Given** 作者仅使用键盘，**When** 在类别、列表和主区域之间移动并激活项目，**Then** 所有关键操作均可到达，当前选择和键盘焦点均清晰可辨。
5. **Given** 窗口处于最小支持尺寸或文本放大到 200%，**When** 作者使用工作区，**Then** 三个区域可以收纳或按需呈现，但当前类别、列表入口、主内容和返回路径始终可达。

---

### User Story 4 - 从独立入口管理全局设置 (Priority: P2)

作为作者，我希望通过一个独立、稳定的 Settings 入口管理 LLM provider、API 密钥、MinerU 和索引服务配置，以便不必在项目内容侧栏中寻找应用级配置，也不会误以为这些配置属于当前项目。

**Why this priority**: 设置是支持 Sections 与知识库的必要辅助能力，但不应与项目内容类别争夺导航层级或混淆配置归属。

**Independent Test**: 从任一项目类别打开 Settings，查看并操作现有 AI provider 与资料处理服务设置，关闭后返回此前工作上下文；切换项目并重启应用后确认全局归属和既有安全行为不变。

**Acceptance Scenarios**:

1. **Given** 作者位于任一项目类别，**When** 激活独立 Settings 入口，**Then** 系统显示应用级设置空间，并清楚区分 LLM/AI provider 配置与资料处理服务配置。
2. **Given** 作者在 Settings 中查看密钥，**When** 配置已经存在，**Then** 系统只显示既有能力允许的脱敏状态，不回显秘密原文。
3. **Given** 作者保存、验证、替换或移除某项配置，**When** 操作完成或失败，**Then** 结果遵循该配置所属功能已经接受的验证、错误和安全规则。
4. **Given** 作者从 Settings 返回，**When** 设置界面关闭，**Then** 系统回到打开设置前的类别、列表选择和合理焦点位置，不重置主工作内容。
5. **Given** 作者切换或移动项目，**When** 再次打开 Settings，**Then** 应用级配置不随项目复制、丢失或被展示为项目内容。

### Edge Cases

- 当前选中的 Section 或资料在列表刷新期间被删除时，系统必须清除失效选择并显示安全默认项或空状态，不能继续展示看似有效的旧详情。
- 大纲标题、资料名称或摘要很长，或者多个项目具有相似名称时，列表必须保留可辨识文本和完整名称的可访问方式，不能只依赖截断内容区分。
- 资料状态快速变化或较早的后台结果迟到时，列表与详情不得出现互相矛盾的版本、计数或检索资格。
- PDF 可以预览但结构化内容尚不可用时，系统必须分别说明原始资料可查看和处理结果尚未就绪，不能把预览成功等同于可检索。
- Markdown 结果包含表格、图片、代码或无法呈现的块时，详情必须保留阅读顺序，并对无法呈现的内容给出可理解占位和块级状态。
- 当前类别没有条目、列表加载失败或 owner 暂不可用时，一级导航和 Settings 入口仍须可用，并提供不泄露内部信息的恢复路径。
- Settings 中存在未提交输入时，返回工作区必须遵循设置 owner 的既有离开和保存规则；导航层不得自行静默提交或丢弃。
- 快速连续切换类别和条目时，最终只能有一个明确的当前类别与当前条目，较早加载结果不得覆盖较新的选择。

## Scope

### In Scope

- 将项目工作区重新组织为窄一级类别栏、上下文列表栏和稳定主内容区。
- 首批一级项目类别为 Sections 与 Knowledge Base，并为当前类别和当前条目提供清晰选择状态。
- Sections 列表消费现有大纲/章节信息，显示标题、摘要、状态和章节关联，并在主区域呈现规划或章节内容。
- Knowledge Base 列表消费现有 PDF 摄取状态，并在主区域呈现原始/处理后内容、内容块数量、索引进度与检索资格。
- 独立 Settings 入口，以及对现有 LLM provider、MinerU 和索引服务配置体验的统一组织与返回行为。
- 类别内工作会话选择的临时恢复、键盘与辅助技术可达性、主题一致性、最小窗口和 200% 文本缩放适配。
- 参考图所表达的信息层级、密度和暗色工作区方向；确切视觉尺寸与样式由后续设计阶段确定。

### Out of Scope

- 在左侧一级类别栏、列表栏或本次主工作区中加入 AI agent 生成或对话窗口。
- 新增 AI agent 工作流、聊天交互、提案审阅或相关导航位置；这些能力留待后续独立规划。
- 新增 PDF 以外的资料导入格式、互联网资料、跨项目知识库或替换已有资料版本。
- 新增 per-Section 的持久化 intention 字段；本次列表使用现有标题与摘要表达 Section 的意图和描述。
- 改变大纲、章节、资料、内容块、索引结果或设置的持久化模型、保存语义、安全边界和业务所有权。
- 重做 PDF 解析、OCR、索引、检索、引用、LLM provider 验证或密钥管理业务逻辑。
- 持久保存类别选择、列表选择、滚动位置、侧栏尺寸或布局偏好；首版只在当前工作会话中恢复。
- 定义最终品牌视觉、逐像素复刻参考图或引入第二套主题、图标和基础组件体系。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 项目工作区 MUST 提供三个可辨识区域：一级类别栏、当前类别列表栏和主内容区；区域之间的视觉与语义层级 MUST 清晰。
- **FR-002**: 一级类别栏首批 MUST 提供 Sections 和 Knowledge Base 两个项目内容类别，并 MUST 将 Settings 作为与项目内容类别有明确区别的独立入口。
- **FR-003**: 系统 MUST 同时只标识一个当前项目内容类别；选择类别后，列表栏和主内容区 MUST 与该类别保持一致。
- **FR-004**: Sections 列表 MUST 按既有大纲顺序显示所有大纲条目，并为每项显示标题、可用摘要、写作状态和是否已有对应章节。
- **FR-005**: 选择已有章节的 Section 时，主内容区 MUST 呈现对应章节及其 Section 上下文；选择尚无章节的 Section 时，主内容区 MUST 呈现规划信息和 owner 提供的明确下一步。
- **FR-006**: Sections 的显示、编辑、保存、删除、排序和章节关联 MUST 继续遵循 003 与 004 已接受的行为；导航层 MUST NOT 自行保存、删除或修改内容。
- **FR-007**: Knowledge Base 列表 MUST 显示当前项目的全部资料记录，并让用户区分等待、解析、索引、部分可用、可用、失败和可重试状态。
- **FR-008**: 选择资料后，主内容区 MUST 显示资料名称、资料级状态、当前版本、内容块总数、有效索引块数、未完成或失败块数以及当前检索资格。
- **FR-009**: 当现有结果可用时，资料详情 MUST 允许用户查看原始 PDF 预览和对应的结构化 Markdown 内容，并 MUST 明确标识当前查看的内容形式及其处理状态。
- **FR-010**: 资料的计数、状态、预览、重试和移除 MUST 来自 006 拥有的当前资料版本与动作；导航层 MUST NOT 推断检索资格、重排块或把部分结果伪装为完整结果。
- **FR-011**: 一级类别与条目切换 MUST 保持主工作区的稳定身份，并 MUST NOT 因导航编排提交、丢弃或重建业务 owner 正在维护的内容状态。
- **FR-012**: 系统 MUST 在当前工作会话中记住每个项目内容类别最近一次有效的条目选择；重新启动应用或重新打开项目时 MUST 使用各 owner 已接受的默认入口，而不是持久恢复本次导航状态。
- **FR-013**: 当前选择失效、owner 不可用或列表加载失败时，系统 MUST 显示安全空状态或错误状态，并提供适用的返回、重试或创建/导入入口。
- **FR-014**: Settings 入口 MUST 从任一项目内容类别可达，并 MUST 清楚说明配置为应用级，而非当前项目内容。
- **FR-015**: Settings MUST 统一组织现有 LLM/AI provider 配置和资料处理服务配置，但每类配置 MUST 继续遵循其 owner 已接受的字段、保存、验证、密钥、错误和数据出境规则。
- **FR-016**: 关闭 Settings 后，系统 MUST 返回打开前的项目内容类别和有效条目选择，并将焦点恢复到 Settings 入口或仍存在的合理回退位置。
- **FR-017**: 本 feature MUST NOT 在一级类别栏、上下文列表栏或主内容区加入 AI agent 对话、AI 生成任务或提案审阅入口。
- **FR-018**: 所有类别、列表项、选择状态、详情模式和操作 MUST 具有明确可访问名称、可见键盘焦点和不依赖颜色或图标的状态表达。
- **FR-019**: 用户 MUST 能仅使用键盘在一级类别栏、列表栏、主内容区和 Settings 之间按可预测顺序移动、选择与返回。
- **FR-020**: 在 System、Light、Dark、高对比、减少动态效果、960×640 和 200% 文本缩放条件下，当前类别、列表入口、主内容、关键状态和 Settings 返回路径 MUST 保持可达。
- **FR-021**: 本 feature MUST 复用 011 与 012 已接受的主题、排版、共享交互、图标映射、操作目标和受控扩展规则，不得建立平行 UI 体系。
- **FR-022**: 本 feature MUST 保持 002 的项目身份、返回项目入口、状态呈现和安全工作区边界，以及 003–006 的数据与业务契约不变；确需改变 durable、IPC、系统或流程边界的设计 MUST 在实施前通过相应 source document 和 ADR gate。

### Key Entities

- **Workspace Category**：一级项目内容类别，首批为 Sections 与 Knowledge Base；定义列表和主内容的当前上下文，但不拥有业务数据。
- **Category Selection**：当前工作会话中被激活的类别，以及该类别最近一次仍有效的条目选择；不跨应用重启持久化。
- **Section Navigation Item**：对现有大纲条目的导航投影，包含标题、可用摘要、写作状态和章节关联，不引入新的 Section 数据记录。
- **Source Navigation Item**：对现有资料记录的导航投影，包含名称、资料类型、处理阶段、进度、错误/重试状态和检索资格摘要。
- **Source Detail Summary**：所选资料当前版本的用户可见详情，包括预览形式、块计数、索引计数、失败范围和检索资格；其事实由资料 owner 提供。
- **Settings Area**：由独立入口打开的应用级配置空间，组织不同 owner 的设置体验，但不合并其密钥、验证或业务所有权。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少 90% 的代表性作者能在首次使用时于 30 秒内从工作区找到指定 Section，并正确说出其写作状态与是否已有章节。
- **SC-002**: 至少 90% 的代表性作者能在 30 秒内找到指定资料，并正确判断其当前处理阶段、内容块总数、索引完成范围和是否可检索。
- **SC-003**: 在连续 100 次 Sections、Knowledge Base、条目和 Settings 切换验证中，100% 最终显示与最新选择一致的列表和主详情，且没有导航造成的内容提交、丢失或错误覆盖。
- **SC-004**: 对等待、解析、索引、部分可用、可用、失败和重试状态的全部基准场景，列表摘要与详情状态达到 100% 一致，且不存在把部分结果或预览成功误报为完整可检索的情况。
- **SC-005**: 100% 的一级类别、列表选择、详情模式和 Settings 打开/返回流程可仅使用键盘完成，并具有可访问名称、可见焦点和明确选择状态。
- **SC-006**: 在 960×640、200% 文本缩放、浅色、深色和高对比组合检查中，当前类别、条目列表、主内容、关键状态和 Settings 返回路径 100% 可达，无阻断性重叠或截断。
- **SC-007**: 003–006 的既有验收与回归场景保持 100% 通过，且本次重构不改变项目内容、资料结果、设置归属、密钥状态或保存语义。
- **SC-008**: 在代表性可用性测试中，至少 80% 的参与者将“容易理解当前所在位置”“容易在 Sections 与知识库间切换”和“设置位置清楚”分别评价为 4 分或 5 分（满分 5 分）。
- **SC-009**: 实施审计中，100% 的本 feature 界面使用已接受的共享 UI 与图标规则或经过 foundation 受控扩展，不存在未经批准的第二套导航、主题、图标或基础控件体系。

## Assumptions and Dependencies

- 002 已提供稳定项目工作区外壳；本 feature 重新组织其已注册内容入口与主工作区呈现，但不改变项目身份、返回启动页或跨边界安全责任。
- 003 与 004 是 Sections 的权威业务来源。本需求中的 Section “intention”和“description”首版映射为现有大纲条目的标题与摘要，不新增持久字段；若后续确认需要独立字段，应先更新相应 source spec、plan 与 ADR gate。
- 005 是 LLM/AI provider 设置的权威来源；006 是 MinerU、索引服务配置、PDF 摄取、内容块和索引状态的权威来源。统一 Settings 只组织入口与呈现，不合并其安全契约。
- 006 当前只接受本地 PDF。用户提到的“其他正在导入的文件”在本 feature 中理解为列表应容纳当前及未来 owner 已正式支持的资料类型，而不是授权本次新增格式。
- 006 已保存原始 PDF 和结构化 Markdown，因此资料详情可以在 owner 明确提供可用结果时展示两种内容形式；本 feature 不重新解析或转换资料。
- 011 与 012 提供主题、排版、共享组件、可访问性和图标规范；具体分栏尺寸、响应式收纳方式和视觉细节在 plan 中依据这些约束确定。
- 首版只面向当前已打开的单个项目；跨项目导航、跨项目知识库和多窗口同步不在范围内。
- AI agent 对话及 AI 生成体验的位置尚未决定，并被明确保留给后续独立 feature，不应通过本次导航设计预留一个可见空入口。

## Dependencies and Sequencing

1. `001-project-foundation`、`011-ui-foundation` 与 `012-icon-usability-refresh` 提供项目身份、共享 UI 和图标/易用性基线。
2. `002-workspace-shell` 提供稳定项目工作区及状态/焦点边界，是本次信息架构重构的直接基础。
3. `003-writing-orientation` 与 `004-block-editor` 提供 Sections 列表和主内容所需的权威数据与行为。
4. `005-provider-settings` 与 `006-source-library-processing` 提供 Settings 和 Knowledge Base 所需的权威配置、资料、处理及索引状态。
5. 本 feature 的 plan 必须确认现有契约是否足以提供分栏视图所需的安全摘要；若需要改变 IPC、持久化或系统边界，必须先更新对应 source document 并通过 ADR gate。
6. `007-source-search-citations` 及后续 AI features 可消费本次导航结构，但不得在本 feature 中提前实现其入口或业务体验。
