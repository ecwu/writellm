# Feature Specification: AI 修改提案审阅

**Feature Branch**: `009-ai-proposal-review`
**Created**: 2026-07-11
**Updated**: 2026-07-12
**Status**: Draft
**Input**: 作者逐项理解、接受、拒绝或暂缓 AI 建议，并在正文变化后仍能安全决定是否应用。

## Clarifications

### Session 2026-07-12

- AI 的修改、新增和删除必须经作者明确接受后才可进入正文。
- 范围扩展建议必须单独确认，不能随普通批量操作被隐式接受。
- 新增内容的位置由提案给出；首版仅支持接受或拒绝该位置。
- 相互依赖的建议必须作为不可拆分变更组整体处理。
- 删除含下级内容或引用关系的内容时，必须完整披露并整体处理；无法安全处理时禁止应用。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 理解每项建议及其影响 (Priority: P1)

作为作者，我希望清楚比较当前内容与 AI 建议，并了解建议的意图、依据、范围和影响，以便在决定前充分知情。

**Why this priority**: 可理解的审阅信息是作者保持最终控制权的前提。

**Independent Test**: 打开包含修改、新增、删除、范围扩展和证据不足的提案，作者可逐项指出会改变什么、为什么改变及影响哪些内容。

**Acceptance Scenarios**:

1. **Given** 提案包含一项修改，**When** 作者查看该项，**Then** 系统清楚区分当前内容与建议内容，并显示目标、意图和依据或证据不足提示。
2. **Given** 提案包含新增内容，**When** 作者查看该项，**Then** 系统显示建议内容、插入位置和相邻上下文。
3. **Given** 提案包含删除，**When** 作者查看该项，**Then** 系统显示将删除的全部内容以及受影响的引用关系。
4. **Given** 建议超出原任务授权范围，**When** 作者查看该项，**Then** 系统醒目标记范围扩展并说明超出的边界。

### User Story 2 - 按自己的节奏处理建议 (Priority: P1)

作为作者，我希望接受、拒绝或暂缓独立建议，并能批量处理适合一起决定的建议，以便只让明确同意的内容进入正文。

**Why this priority**: 细粒度、可恢复的决策避免整份 AI 输出覆盖作者判断。

**Independent Test**: 对多项建议分别接受、拒绝和暂缓，确认只有接受项改变正文，其余状态在离开和重新打开后仍保留。

**Acceptance Scenarios**:

1. **Given** 提案包含多个独立建议，**When** 作者接受其中一项，**Then** 只应用该项，其他项保持原审阅状态。
2. **Given** 作者拒绝一项建议，**When** 操作完成，**Then** 正文不包含该建议，且拒绝决定被保留。
3. **Given** 作者暂缓一项建议，**When** 作者离开后再次打开提案，**Then** 该项仍处于待决定状态并可继续审阅。
4. **Given** 作者批量处理建议，**When** 批量范围包含范围扩展项，**Then** 范围扩展项不会被普通批量接受，必须单独确认。
5. **Given** 多项建议属于同一不可拆分变更组，**When** 作者处理组内任一项，**Then** 系统只允许整体接受或整体拒绝，并显示全部成员和影响。

### User Story 3 - 避免覆盖较新的正文 (Priority: P1)

作为作者，我希望系统在应用前识别提案与当前正文不再一致的情况，以便不会静默覆盖任务完成后的手动编辑。

**Why this priority**: 过期与冲突保护决定提案应用是否可信。

**Independent Test**: 在提案生成后修改相关正文，再尝试应用旧建议，确认系统阻止静默覆盖并提供重新审阅或重新生成的下一步。

**Acceptance Scenarios**:

1. **Given** 相关正文在提案生成后已变化，**When** 作者尝试应用建议，**Then** 系统在写入前标记过期或冲突，并要求重新审阅或重新生成。
2. **Given** 建议位置或目标无法唯一对应当前正文，**When** 作者尝试应用，**Then** 系统阻止应用且不自行猜测新目标。
3. **Given** 一组已接受建议全部仍可安全应用，**When** 保存成功，**Then** 正文仅包含这些建议，并保留其任务来源。
4. **Given** 应用或保存失败，**When** 作者查看结果，**Then** 系统不报告成功，并清楚说明正文当前状态和可重试操作。

### Edge Cases

- 建议互相重叠、冲突或无法确定顺序时，必须阻止静默合并并要求作者判断。
- 批量操作中某项无法应用时，系统必须在确认前说明批量操作能否整体完成；不得留下状态不明的部分结果。
- 不可拆分变更组中任何成员不可应用时，整个组不得改变正文。
- 删除建议无法完整定位下级内容或安全处理引用时，整个删除不得应用。
- 建议依据的资料已失效时，应用前必须提醒作者重新判断。
- 范围扩展项不得默认选中或通过“全部接受”绕过单独确认。

## Scope

### In Scope

- 查看修改、新增和删除建议的当前内容、建议结果、意图、依据和影响。
- 接受、拒绝、暂缓和批量处理建议。
- 单独确认范围扩展，整体处理不可拆分变更组。
- 识别过期、冲突、无法定位和失效依据，并安全应用作者接受的建议。
- 保留任务来源和审阅状态。

### Out of Scope

- 创建或执行 AI 写作任务；由 `008-ai-writing-tasks` 负责。
- 调整 AI 建议的插入位置。
- 无需作者确认而自动改变正文。
- 浏览、比较或恢复任意历史版本；由 `010-version-history` 负责。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 每项建议 MUST 显示操作类型、目标或位置、当前内容、建议结果和变更意图；不适用的信息可省略但不得误导。
- **FR-002**: 每项建议 MUST 显示资料依据、证据不足或依据已失效状态。
- **FR-003**: 作者 MUST 能对独立建议执行接受、拒绝或暂缓，并在稍后继续审阅未决定项。
- **FR-004**: 作者 MUST 能批量接受或拒绝符合批量条件的待处理建议。
- **FR-005**: 系统 MUST 只把作者明确接受且仍可安全应用的建议写入正文。
- **FR-006**: 系统 MUST 保留所有未应用建议及其待处理、已拒绝或暂缓状态。
- **FR-007**: 范围扩展建议 MUST 醒目标记、说明扩展边界、要求单独确认，且 MUST NOT 被普通批量接受。
- **FR-008**: 新增内容 MUST 展示建议位置和相邻上下文；位置失效或无法唯一识别时 MUST 阻止应用。
- **FR-009**: 相互依赖的建议 MUST 作为不可拆分变更组整体接受或拒绝；任何成员不可应用时整个组 MUST NOT 改变正文。
- **FR-010**: 删除含下级内容或引用关系时，系统 MUST 在确认前展示完整影响；无法完整确定或安全处理时 MUST 阻止整个删除。
- **FR-011**: 当前正文与提案依据不再一致时，系统 MUST 在写入前标记过期或冲突，并要求重新审阅或重新生成。
- **FR-012**: 重叠、冲突或无法定位的建议 MUST NOT 被自动合并或自动改选目标。
- **FR-013**: 成功应用的建议 MUST 保留对应任务和资料来源，供作者追踪。
- **FR-014**: 应用或保存失败时，系统 MUST NOT 报告成功，并 MUST 说明正文当前状态和可用的重试操作。

### Key Entities

- **修改提案**：等待作者审阅的一组 AI 建议。
- **提案建议**：一项修改、新增或删除建议及其依据、范围、影响和审阅状态。
- **审阅状态**：待处理、已接受、已拒绝或暂缓。
- **范围扩展**：超出原任务授权正文或位置的建议，需要独立确认。
- **不可拆分变更组**：必须共同处理才能保持完整含义的一组建议。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少 90% 的目标用户能在 60 秒内指出一项建议会改变什么、依据什么以及是否超出授权范围。
- **SC-002**: 在覆盖接受、拒绝、暂缓和批量操作的验收样本中，100% 的正文只包含作者明确接受且成功应用的建议。
- **SC-003**: 100% 的过期、冲突或无法定位建议都在写入前被阻止或提示，不覆盖较新的手动修改。
- **SC-004**: 100% 的范围扩展项都经过单独确认，不会被普通批量接受。
- **SC-005**: 100% 的不可拆分变更组和含下级内容的删除，要么完整应用，要么完全不改变正文。
- **SC-006**: 至少 90% 的目标用户能在 2 分钟内完成一次包含接受、拒绝或暂缓的部分审阅，并继续编辑正文。
- **SC-007**: 100% 的应用或保存失败都不会显示为成功，且作者能看见正文当前状态和下一步。

## Assumptions and Dependencies

- 本 feature 接收 `008-ai-writing-tasks` 产生的提案，并依赖现有正文和资料引用可供作者查看。
- 只有作者明确接受且成功保存的建议才成为正文内容。
- 成功应用的内容变化会作为新的已保存版本出现在 `010-version-history` 中。
