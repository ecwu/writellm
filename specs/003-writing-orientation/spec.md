# Feature Specification: 写作动机与文章大纲

**Feature Branch**: `003-writing-orientation`

**Created**: 2026-07-11

**Status**: Draft

**Input**: 从原 `001-ai-writing-workspace` 拆分：在项目中记录写作动机、维护大纲，并恢复作者上次的写作方向。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 记录写作动机 (Priority: P1)

作为作者，我希望记录文章要解决的问题、目标读者和预期结果，以便在写作过程中保持方向。

**Why this priority**: 动机是作者判断章节内容和后续辅助请求是否有价值的共同上下文。

**Independent Test**: 打开一个空项目，填写并保存动机，关闭后重新打开，确认内容完整恢复。

**Acceptance Scenarios**:

1. **Given** 项目尚未填写动机，**When** 用户输入内容并保存，**Then** 系统显示已保存状态。
2. **Given** 项目已有动机，**When** 用户再次编辑并保存，**Then** 系统只更新动机，不影响大纲或章节。

### User Story 2 - 建立和调整文章大纲 (Priority: P1)

作为作者，我希望新增、编辑、删除和排序大纲条目，以便明确文章结构和下一步工作。

**Why this priority**: 大纲把写作目标转化成可执行的章节计划，是章节编辑的入口。

**Independent Test**: 新增至少三个条目，修改标题和摘要，调整顺序并删除一个；重新打开后确认顺序和内容正确。

**Acceptance Scenarios**:

1. **Given** 项目已有大纲，**When** 用户新增、编辑或删除条目，**Then** 列表即时反映变化并可保存。
2. **Given** 大纲包含多个条目，**When** 用户调整条目顺序，**Then** 新顺序在重新打开后保持不变。
3. **Given** 某条目尚未开始，**When** 用户查看大纲，**Then** 系统显示其状态和是否已有对应章节。

### User Story 3 - 恢复写作方向 (Priority: P2)

作为作者，我希望重新打开项目后看到上次保存的动机、大纲和当前位置，以便快速继续工作。

**Why this priority**: 恢复上下文能让作者在多个项目之间切换而不丢失写作计划。

**Independent Test**: 保存动机、大纲和当前位置，重启应用并打开项目，确认三者都恢复。

**Acceptance Scenarios**:

1. **Given** 项目已有动机和大纲，**When** 用户重新打开项目，**Then** 系统恢复最近一次已保存的内容和编辑位置。
2. **Given** 用户有未保存修改，**When** 用户离开项目，**Then** 系统明确提示未保存状态，不将未保存内容伪装为已保存。

### Edge Cases

- 动机为空时允许保存，但界面应明确表示尚未填写。
- 大纲标题为空或仅包含空白字符时不得保存。
- 删除已有章节关联的大纲条目时，系统必须先提示影响，不得静默删除章节。
- 调整顺序或重复提交保存时，不能产生重复条目或错误顺序。
- 文本过长、包含不支持的控制字符或保存失败时，系统给出可执行的修改或重试提示。

## Scope

### In Scope

- 写作动机的创建、编辑、保存和恢复。
- 大纲条目的创建、编辑、删除、排序和状态展示。
- 大纲条目与未来章节的关联状态展示。

### Out of Scope

- 章节正文和 Block 编辑。
- 资料库、检索、AI 任务和版本历史。
- 多层嵌套大纲和多人协作。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为每个项目提供独立的写作动机区域。
- **FR-002**: 用户 MUST 能够新增、编辑、删除和重新排序大纲条目。
- **FR-003**: 每个大纲条目 MUST 支持标题、摘要、状态和可选的章节关联信息。
- **FR-004**: 系统 MUST 保持大纲条目的显示顺序，并在重新打开项目后恢复该顺序。
- **FR-005**: 系统 MUST 显示大纲条目是否尚未开始、进行中或已完成。
- **FR-006**: 保存动机或大纲时，系统 MUST 不改变其他项目内容。
- **FR-007**: 保存失败时系统 MUST 保留当前可恢复编辑状态，并明确提示用户重试。
- **FR-008**: 用户离开项目时，系统 MUST 区分已保存内容和未保存修改。

### Key Entities

- **写作动机**：关于文章目标、读者、问题和预期结果的说明。
- **大纲文档**：项目中按顺序排列的大纲条目集合。
- **大纲条目**：一个计划中的主题或章节，包含标题、摘要、状态和可选章节关联。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少 90% 的作者能在 5 分钟内填写动机并创建两个大纲条目。
- **SC-002**: 在 100 次保存和重新打开测试中，100% 的动机文本和大纲顺序保持一致。
- **SC-003**: 至少 95% 的用户能在 30 秒内完成一次大纲条目排序。
- **SC-004**: 100% 的空标题、重复条目或保存失败场景都给出明确反馈。

## Assumptions

- 本 feature 依赖 `001-project-foundation` 和 `002-workspace-shell` 提供有效项目和基本工作台能力。
- 首版大纲为单层有序列表，不要求树状嵌套。
- 大纲可以先存在而没有对应章节；章节创建由 `003-block-editor` 负责。
