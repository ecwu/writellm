# Feature Specification: 全界面图标与易用性改进

**Feature Branch**: `012-icon-usability-refresh`

**Created**: 2026-07-12

**Status**: Accepted — maintainer accepted on 2026-07-13.

**Input**: 在项目中引入 ShareCM 推荐的图标库，并让整个界面更易用。

## Clarifications

### Session 2026-07-13

- Q: 用户测试样本量如何约束？ → A: 人数不设硬性门槛；约 5 人仅作为执行预期。
- Q: 改进前基线如何取得？ → A: 不要求基线，删除相对改善指标。
- Q: 高严重度审计问题的保留由谁审批？ → A: 产品与无障碍评审共同批准。
- Q: 图标控件的最小操作目标是多少？ → A: 至少 44×44 CSS px。
- Q: 仅图标控件在什么条件下准入？ → A: 辅助操作、空间受限、图标惯例明确且通过审计四项条件必须全部满足。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 快速识别常用操作 (Priority: P1)

作为作者，我希望项目入口、工作台、大纲和编辑器中的常用操作使用一致、熟悉且易辨认的图标与文字，以便我能更快找到下一步，并避免把移动、删除、返回、保存或导出等操作弄混。

**Why this priority**: 操作发现性和辨识度直接影响所有已实现流程；高频或高风险操作若表达含糊，会造成重复寻找和误操作。

**Independent Test**: 在启动页、工作台、大纲和章节编辑器中抽取创建、打开、返回、保存、移动、删除、粘贴、导出和关闭操作，验证图标含义、文字、位置和状态一致，并由目标用户完成代表性任务。

**Acceptance Scenarios**:

1. **Given** 用户打开任一已实现界面，**When** 查看可执行操作，**Then** 适合图形表达的常用操作具有来自同一视觉体系的图标，且相同动作在不同界面使用相同图标和名称。
2. **Given** 操作可能造成数据丢失、删除或离开当前上下文，**When** 用户查看该操作，**Then** 危险程度和结果通过清晰文字、位置与视觉状态共同表达，不依赖图标猜测。
3. **Given** 操作不可用或正在执行，**When** 用户查看或尝试该操作，**Then** 禁用、忙碌或完成状态仍清晰可辨，图标不会掩盖原因或状态反馈。

---

### User Story 2 - 无障碍地理解和使用图标操作 (Priority: P1)

作为使用键盘、屏幕阅读器、放大显示或高对比模式的作者，我希望图标不会取代必要的名称、焦点和状态信息，以便我无需依赖视力、颜色或精确指针操作也能完成工作。

**Why this priority**: 图标只有在保留可访问名称和多通道反馈时才会提升易用性；否则会让现有界面对部分用户更难使用。

**Independent Test**: 仅使用键盘和辅助技术遍历所有图标相关控件，并在浅色、深色、高对比和 200% 文本缩放条件下验证名称、焦点、提示、目标尺寸和状态。

**Acceptance Scenarios**:

1. **Given** 控件只显示图标，**When** 键盘焦点、指针悬停或辅助技术读取该控件，**Then** 用户能获得明确的动作名称；补充提示不会成为控件的唯一名称。
2. **Given** 用户仅使用键盘，**When** 遍历并激活图标相关操作，**Then** 每个操作均可到达、具有可见焦点，并按既有键盘契约执行。
3. **Given** 用户启用高对比、深色主题、减少动态效果或 200% 文本缩放，**When** 使用相关界面，**Then** 图标、文字、焦点和状态仍可辨认，主要操作不会因拥挤或截断而不可达。

---

### User Story 3 - 在清晰的信息层级中完成写作任务 (Priority: P2)

作为作者，我希望整个界面的主要操作、次要操作、危险操作、状态反馈和空状态有清晰且一致的层级，以便我无需逐个阅读所有控件也能理解当前上下文和推荐的下一步。

**Why this priority**: 图标统一解决视觉语言问题，而整体易用性还取决于操作分组、优先级、反馈和页面密度是否支持真实任务。

**Independent Test**: 使用首次创建并打开项目、建立大纲并排序、开始章节、保存和导出五条代表性流程，记录任务完成情况、错误次数、操作发现性和界面层级评价。

**Acceptance Scenarios**:

1. **Given** 一个界面同时存在多个操作，**When** 用户进入该界面，**Then** 主要下一步、辅助操作和危险操作通过分组、顺序、标签与视觉权重形成明确层级。
2. **Given** 列表为空、数据加载失败、内容未保存或操作成功，**When** 对应状态出现，**Then** 用户看到与当前上下文相关的解释和可执行下一步。
3. **Given** 用户在窄窗口或放大文本下操作，**When** 操作区无法保持单行，**Then** 控件可合理换行或收纳，且动作名称、顺序和可达性不丢失。

### Edge Cases

- 推荐图标集中没有完全对应的业务概念时，必须优先保留清晰文字，并选择经用户验证后不会与其他动作混淆的通用图标；不得临时混入第二套图标风格。
- 同一图标可能表达多个动作时，必须通过稳定文字或可访问名称消除歧义，不得仅依赖所在位置。
- 图标资源无法呈现时，控件的名称、布局和操作能力仍须可用，不能出现空白的无名按钮。
- 翻译后标签变长、窗口变窄或文本放大到 200% 时，操作区可以换行或降低非必要装饰，但不得隐藏主要操作或截断关键名称。
- 禁用、保存中、错误、成功、选中和未选中状态不得只靠图标形状、颜色或动画区分。
- 删除、丢弃、离开等高风险操作不得因为图标化而失去确认、警示或既有离开保护。
- 拖放不可用时，大纲排序仍须保留明确且可访问的替代操作，并使用一致的移动图标与名称。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在所有当前已实现的用户界面中采用单一、项目批准的推荐图标体系，不得为同类产品操作并行使用风格不一致的图标来源。
- **FR-002**: 团队 MUST 建立并维护一份操作到图标、可见名称、可访问名称、使用位置和风险级别的统一映射，覆盖至少创建、打开、返回、保存、添加、移动、删除、关闭、粘贴、导出、设置和工作台工具入口。
- **FR-003**: 相同操作在不同界面 MUST 使用相同的核心名称和图标；同一图标不得在没有明确上下文标签的情况下代表含义冲突的操作。
- **FR-004**: 系统 MUST 对启动页、工作台外壳、写作导向、大纲管理和章节编辑器的所有可见操作与状态完成一次易用性审计，并记录每项问题的处理结果或保留理由；任何高严重度问题的保留 MUST 经产品与无障碍评审共同批准，并记录补偿措施。
- **FR-005**: 每个仅显示图标的交互控件 MUST 具有独立、明确且与结果一致的可访问名称，并在焦点或悬停时提供补充说明；补充说明 MUST NOT 是唯一名称来源。
- **FR-006**: 主要业务动作 SHOULD 默认保留可见文字；只有同时属于辅助操作、空间受限、图标惯例明确且经审计无歧义时，控件 MAY 使用仅图标形式。
- **FR-007**: 系统 MUST 通过布局、分组、顺序和视觉权重区分主要、次要与危险操作，并确保每个界面最多只有一个与当前上下文对应的主要下一步。
- **FR-008**: 系统 MUST 用一致方式呈现默认、悬停、键盘焦点、按下、选中、禁用、忙碌、成功、警告和错误状态；任何状态含义不得只由颜色、图标或动画表达。
- **FR-009**: 所有图标相关控件 MUST 保持现有可访问键盘操作、可见焦点和至少 44×44 CSS px 的指针操作目标，且不得缩小既有可用点击区域。
- **FR-010**: 系统 MUST 在浅色、深色、高对比、减少动态效果、最小受支持窗口和 200% 文本缩放条件下保持主要操作、名称、图标和反馈可辨且可达。
- **FR-011**: 空状态、失败状态、未保存状态和完成反馈 MUST 说明当前情况，并在用户可采取行动时提供明确且上下文相关的下一步。
- **FR-012**: 本 feature MUST 保持现有项目、外观、工作台、写作导向、章节编辑和导出业务行为、数据格式、持久化边界及进程间契约不变。
- **FR-013**: 图标 MUST 随应用提供并可离线呈现；运行时不得依赖远程图标服务、远程字体或外部资源。
- **FR-014**: 新增或修改界面操作时 MUST 遵循统一图标映射和可访问性规则；确需新增图标或例外时，必须记录含义、复用范围和验证责任。
- **FR-015**: 系统 MUST 删除被新图标替代的装饰性字符或重复视觉标记，避免辅助技术重复朗读或用户看到相互冲突的动作表达。

### Key Entities

- **Action Icon Mapping**: 一个产品动作与其标准图标、可见名称、可访问名称、风险级别、允许的呈现形式和使用位置之间的统一关系。
- **Interface Audit Finding**: 在某一界面发现的易用性问题，包括所在流程、影响用户、严重程度、预期改进、处理状态和验证证据。
- **Action Priority**: 操作在当前上下文中的主要、次要或危险等级，用于约束分组、顺序、文字保留和视觉权重。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 启动页、工作台外壳、写作导向、大纲管理和章节编辑器中 100% 的可见交互控件完成审计，且所有高严重度发现均已解决或有明确、经评审的保留理由。
- **SC-002**: 100% 的仅图标控件具有准确的可访问名称、可见键盘焦点和可通过焦点或悬停获得的补充说明；辅助技术不会重复朗读装饰性图标。
- **SC-003**: 操作映射所覆盖的同类动作在不同界面达到 100% 的图标和核心名称一致性，审计中不存在未经批准的第二套图标风格。
- **SC-004**: 在代表性用户测试中，至少 90% 的参与者能在首次尝试中完成创建并打开项目、建立并排序大纲、开始章节、保存和导出这五条流程。
- **SC-006**: 在浅色、深色、高对比、最小受支持窗口和 200% 文本缩放组合检查中，100% 的主要操作保持可辨、可达且不发生阻断性截断或重叠。
- **SC-007**: 既有功能验收和回归检查保持 100% 通过，且图标与布局改进不改变任何项目或文档内容结果。
- **SC-008**: 在完成代表性流程后，至少 80% 的测试参与者将“容易找到操作”和“界面层级清晰”评价为 4 分或 5 分（满分 5 分）。

## Assumptions

- 用户输入中的“ShareCM”指当前项目采用的 shadcn/ui 组件体系；其推荐且项目已具备的图标体系作为唯一默认来源。确切依赖、版本和接入方式由 implementation plan 依据已接受的 UI foundation 决定。
- 本 feature 覆盖实施时仓库中已经可用的启动页、工作台、写作导向、大纲和章节编辑体验；尚未实现的资料库、AI、版本历史和完整设置界面不在本次逐页改造范围内，但未来必须遵循本 feature 形成的规则。
- “更易用”默认包括操作发现性、命名一致性、信息层级、状态反馈、键盘与辅助技术可达性、窄窗口和文本缩放适配；不包括重定义现有业务流程或新增业务能力。
- 可见文字与图标组合是主要操作的默认形式；仅图标控件限于空间受限且含义明确的辅助操作。
- 用户测试预计邀请约 5 名熟悉桌面写作工具但未参与实现的代表性参与者；具体人数不构成验收门槛，也不要求记录改造前基线。

## Scope Boundaries

### In Scope

- 为所有已实现界面建立统一动作图标映射，并替换字符箭头、混杂图标或缺少图形提示的适合场景。
- 审计并改进操作命名、按钮层级、分组、密度、空状态、错误/保存反馈、窄窗口和文本放大表现。
- 为仅图标控件补齐可访问名称、补充说明、键盘焦点和状态表达。
- 为后续 renderer 功能记录图标选择、例外和验证规则。
- 对现有代表性用户流程执行任务完成、错误、操作发现性和界面层级验证。

### Out of Scope

- 改变项目、recent、外观、写作导向、章节、引用或导出数据模型、持久化行为、IPC 契约和安全边界。
- 新增资料库、AI 写作、版本历史、完整设置或其他尚未实现的业务界面。
- 创建品牌插画、应用 logo、文件类型图标、动态图标或独立发布的设计系统。
- 使用仅图标界面替代清晰文字，或为追求视觉简洁而隐藏主要操作。
- 在运行时访问远程图标目录、字体或图像服务。

## Dependencies and Sequencing

1. `011-ui-foundation` 是本 feature 的硬依赖，提供共享组件、主题、提示和可访问性契约。
2. `001-project-foundation`、`002-workspace-shell`、`003-writing-orientation` 和 `004-block-editor` 的已接受行为与完成实现共同构成本次界面审计和回归基线。
3. 本 feature 的 plan 必须确认是否需要补充 ADR；若只消费 ADR-003 已接受的 UI ownership 与依赖边界，则可明确记录为不需要新 ADR。
4. 005–010 的未来 renderer 界面应在实现时消费本 feature 的图标映射与易用性规则，而不要求本 feature 预先实现其业务界面。
