# Feature Specification: 写作工作台外壳

**Feature Branch**: `002-workspace-shell`

**Created**: 2026-07-11

**Status**: Draft

**Input**: 从原 `001-ai-writing-workspace` 的 implementation plan 拆分：进入项目后提供持久、可访问、不会因打开面板而重建编辑上下文的工作台外壳。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在稳定工作台中写作 (Priority: P1)

作为作者，我希望进入项目后看到持续存在的顶部导航、工具栏、编辑区域和底部快捷操作，以便在不同工作区工具之间切换而不丢失当前上下文。

**Why this priority**: 工作台是所有后续写作、资料和 AI 功能共享的交互边界。

**Independent Test**: 打开一个有效项目，在编辑区输入临时内容，打开和关闭工具面板，确认编辑上下文和焦点不被重置。

**Acceptance Scenarios**:

1. **Given** 用户已打开项目，**When** 工作台加载完成，**Then** 系统展示项目导航、工具入口、主要编辑区域和状态区域。
2. **Given** 用户正在编辑，**When** 用户打开或切换一个工具面板，**Then** 编辑区域保持当前内容、选区和滚动位置。
3. **Given** 用户关闭面板，**When** 关闭动作完成，**Then** 焦点回到触发面板的入口或合理的编辑位置。

### User Story 2 - 使用可理解的面板和模态操作 (Priority: P1)

作为作者，我希望面板和模态窗口有一致的打开、关闭、焦点和键盘行为，以便不会被界面状态困住。

**Why this priority**: 桌面写作工具需要高频切换上下文；不一致的浮层行为会直接破坏写作流。

**Independent Test**: 分别通过鼠标、键盘和 Escape 打开/关闭面板与模态，验证焦点、背景滚动和外部点击行为。

**Acceptance Scenarios**:

1. **Given** 一个工具面板已打开，**When** 用户点击同一工具入口或按 Escape，**Then** 面板关闭并恢复合理焦点。
2. **Given** 一个设置模态已打开，**When** 用户操作模态，**Then** 背景不可误操作，焦点停留在模态内。
3. **Given** 用户在窄窗口中使用工作台，**When** 窗口尺寸变小，**Then** 入口仍可访问并显示必要的文字或提示。

### User Story 3 - 识别工作台状态 (Priority: P2)

作为作者，我希望在工作台中看到保存中、已保存、错误和需要处理的状态，以便知道下一步该做什么。

**Why this priority**: 状态可见性是安全保存和后续功能接入的基础。

**Independent Test**: 模拟保存中、保存成功和保存失败状态，确认状态不仅依赖颜色，并提供可执行操作。

**Acceptance Scenarios**:

1. **Given** 内容正在保存，**When** 用户查看工作台，**Then** 系统显示文字或图标状态，不把内容显示为已保存。
2. **Given** 保存失败，**When** 用户查看状态区域，**Then** 系统显示原因摘要和重试或恢复入口。
3. **Given** 面板或模态打开，**When** 状态发生变化，**Then** 用户仍能发现重要错误和未保存提示。

### Edge Cases

- 同时触发多个面板入口时，系统只保留一个明确的活动面板。
- Escape、外部点击和触发按钮关闭行为不能互相冲突。
- 键盘用户不得因为浮层打开而失去可达路径。
- 背景编辑器很长或正在滚动时，模态背景效果不得造成内容不可读或无法滚动。
- 工作台最小窗口尺寸下，主要写作区域和保存状态仍可访问。

## Scope

### In Scope

- 持久化 Workspace Shell 的布局和状态边界。
- 顶部项目导航、左侧工具入口、中心编辑区域和底部快捷操作。
- 工具面板、模态窗口、焦点管理、Escape、外部点击和背景滚动规则。
- 键盘可达性、窄窗口布局和保存/错误状态展示。

### Out of Scope

- 章节编辑内容本身，由 `004-block-editor` 负责。
- 资料、AI、引用和历史的具体业务逻辑。
- Provider secret 的保存和验证，由 `005-provider-settings` 负责。
- 多窗口、远程协作和完整路由系统。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为已打开项目提供持续存在的工作台外壳。
- **FR-002**: 工作台 MUST 提供项目导航、工具入口、主要编辑区域和状态区域。
- **FR-003**: 打开或切换面板时，系统 MUST 保持主要编辑区域的内容和编辑上下文。
- **FR-004**: 同一时间 MUST 只允许一个工具面板处于活动状态，且切换行为必须可预测。
- **FR-005**: 模态窗口 MUST 管理焦点、Escape、背景滚动和关闭后的焦点恢复。
- **FR-006**: 所有图标入口 MUST 提供可访问名称或等价的文字提示。
- **FR-007**: 工作台 MUST 在宽屏和最小支持窗口下保持主要入口可访问。
- **FR-008**: 保存中、已保存、错误和需要处理状态 MUST 同时提供文字或图标等非颜色信息。
- **FR-009**: 外部点击或 Escape 关闭浮层时，系统 MUST 不丢失当前编辑内容。

### Key Entities

- **工作台外壳**：项目打开后持续存在的导航、工具和状态布局。
- **工具面板**：由工具入口打开的上下文面板，同一时间最多一个活动面板。
- **模态窗口**：需要用户完成配置或确认的聚焦式界面。
- **工作台状态**：当前项目、活动面板、打开模态、保存状态和错误状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少 95% 的作者能在 30 秒内找到项目导航、主要编辑区和保存状态。
- **SC-002**: 在 100 次面板切换测试中，100% 不丢失当前编辑内容和选区状态。
- **SC-003**: 至少 90% 的键盘用户能不使用鼠标完成打开、浏览和关闭一个面板。
- **SC-004**: 100% 的模态关闭测试都能恢复合理焦点，且背景不会被误操作。
- **SC-005**: 在 960×640 的最小窗口测试中，主要编辑区和保存错误入口仍可访问。

## Assumptions

- 本 feature 依赖 `001-project-foundation` 提供有效项目和项目切换入口。
- 工作台只定义共享交互外壳，不预先实现资料、AI 或历史的业务逻辑。
- 具体业务 feature 通过明确的面板入口接入，不重复实现工作台壳层。
