# Feature Specification: 写作工作台外壳

**Feature Branch**: `002-workspace-shell`

**Created**: 2026-07-11

**Updated**: 2026-07-12

**Status**: Accepted — maintainer accepted 2026-07-12; 011 implementation confirmed complete

**Input**: 基于已实现的 `001-project-foundation` 和已接受设计、正在进入实施规划的 `011-ui-foundation`，更新项目打开后的工作台外壳范围：复用既有项目入口与共享 UI foundation，只定义稳定布局、工作区槽位、工具面板编排、焦点恢复、响应式可达性和 owner-provided 状态呈现。

## Clarifications

### Session 2026-07-12

- Q: 002 何时接受？ → A: 现在接受；011 已实现完成。
- Q: 尚未实现的工具入口如何呈现？ → A: 未注册工具完全隐藏，后续 feature 接入时再出现。
- Q: 打开普通工具面板后的焦点与临时预览行为？ → A: 焦点保留在入口，下一次 Tab 进入面板；hover 只临时预览，点击或键盘激活后固定打开且不因失焦或超时关闭。
- Q: 返回启动页是否需要阻拦机制？ → A: 002 始终直接返回并清除 shell session，不预建导航阻拦。
- Q: 多个 owner 同时报告状态时如何显示？ → A: 只显示固定优先级选出的最高优先级主状态。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从已打开项目进入稳定工作台 (Priority: P1)

作为作者，我希望在创建、打开或重新关联项目后进入一个清楚标识当前项目的稳定工作台，以便继续后续写作流程，而不必重新选择项目。

**Why this priority**: 001 已经可靠地建立项目身份和打开流程；002 的首要价值是把这一结果交接给可供后续功能复用的项目内工作区。

**Independent Test**: 分别通过 001 的创建、打开、最近项目打开和移动后重新关联流程进入工作台，确认工作台显示同一项目摘要、提供返回启动页的明确入口，并且不改变 001 的项目或最近记录行为。

**Acceptance Scenarios**:

1. **Given** 用户通过 001 成功创建或打开有效项目，**When** 打开结果交给工作台，**Then** 系统进入工作台并显示当前项目的名称、工作区主体和状态区域。
2. **Given** 用户通过最近项目或重新关联恢复同一稳定项目身份，**When** 工作台显示，**Then** 系统延续该项目身份，不创建重复项目或最近记录。
3. **Given** 用户位于工作台，**When** 用户选择返回项目入口，**Then** 系统回到 001 启动页，并继续使用 001 已有的新建、打开和最近项目能力。
4. **Given** 项目打开失败、取消或仍然无效，**When** 001 返回相应结果，**Then** 系统不进入工作台，也不把失败状态伪装成已打开项目。

---

### User Story 2 - 在工具切换中保持主要工作上下文 (Priority: P1)

作为作者，我希望使用项目导航和工具面板时，主要工作区域持续存在，以便后续编辑器或其他内容功能接入后，切换辅助工具不会重置正在进行的工作。

**Why this priority**: 工作区槽位的稳定身份是 002 区别于普通页面布局的核心承诺，也是后续编辑、资料和 AI 功能可以安全接入的前提。

**Independent Test**: 在主要工作区放入可观察的测试内容，连续打开、切换和关闭工具面板，确认主要工作区节点、内容、选区、滚动位置和焦点上下文未因 shell 编排而重建或丢失。

**Acceptance Scenarios**:

1. **Given** 用户已进入工作台，**When** 工作台加载完成，**Then** 系统展示项目导航、工具入口、主要工作区槽位和状态区域。
2. **Given** 主要工作区已有内容、选区或滚动位置，**When** 用户打开、切换或关闭工具面板，**Then** shell 保持主要工作区及其当前上下文。
3. **Given** 一个工具面板已打开，**When** 用户选择另一个工具入口，**Then** 新面板替换原面板，且同一时间只有一个活动工具面板。
4. **Given** 用户重复选择当前活动的工具入口或按 Escape，**When** 当前面板允许关闭，**Then** 面板关闭并把焦点恢复到触发入口或合理的主要工作位置。
5. **Given** 一个普通工具面板通过入口打开，**When** 面板变为可见，**Then** 焦点保留在入口，键盘用户下一次按 Tab 时进入面板。
6. **Given** 用户尚未固定打开工具面板，**When** 指针 hover 工具入口，**Then** 系统临时预览对应面板；指针离开入口与预览区域并经过短暂宽限后自动收回。
7. **Given** 用户点击工具入口或用键盘激活，**When** 面板固定打开，**Then** 面板不得因失焦、指针离开或超时自动关闭，只能通过再次激活入口、Escape 或显式关闭退出。

---

### User Story 3 - 使用一致、可访问的工作台交互 (Priority: P1)

作为作者，我希望工作台沿用应用的主题、组件、排版、焦点和浮层规则，以便在鼠标、键盘、不同主题和窄窗口条件下都能理解并完成操作。

**Why this priority**: 011 已把这些行为定义为跨 feature 基础；002 必须消费同一套规则，才能避免工作台形成第二套不一致的界面体系。

**Independent Test**: 在 System、Light、Dark、减少动态效果、键盘操作、200% 文本缩放和最小支持窗口条件下遍历工作台入口、面板和示例模态，验证主要区域和关闭路径始终可达。

**Acceptance Scenarios**:

1. **Given** 用户已选择一种 011 支持的外观偏好，**When** 用户从启动页进入工作台，**Then** 工作台沿用有效主题和排版规则，不闪回或建立独立主题状态。
2. **Given** 用户仅使用键盘，**When** 用户遍历导航、工具入口、面板和模态操作，**Then** 每个交互都有可访问名称、可见焦点和可预测的关闭路径。
3. **Given** 一个模态操作已打开，**When** 用户使用 Tab、Shift+Tab、Escape 或显式关闭，**Then** 焦点受约束、背景不可误操作，关闭后焦点恢复到合理位置。
4. **Given** 窗口处于 960×640 或文本缩放到 200%，**When** 用户操作工作台，**Then** 当前项目、主要工作区、工具入口和重要状态仍可到达，不发生阻断性截断。

---

### User Story 4 - 理解各功能提供的工作状态 (Priority: P2)

作为作者，我希望在统一状态区域看到当前功能提供的进行中、完成、错误或需要处理状态，以便判断下一步行动，同时不会把尚未确认的操作误认为已完成。

**Why this priority**: shell 需要为后续功能提供一致的状态呈现位置，但真实保存、重试和恢复结果必须继续由拥有该业务的 feature 决定。

**Independent Test**: 向工作台提供不同的标准化状态摘要，确认 shell 正确显示文字、严重程度和可用操作；当状态缺失、未知或 owner 不可用时，确认 shell 使用安全退化呈现且不自行执行持久化。

**Acceptance Scenarios**:

1. **Given** 某功能报告进行中或已完成状态，**When** 工作台接收状态摘要，**Then** 状态区域以文字和语义信息显示实际状态，不仅依赖颜色。
2. **Given** 某功能报告错误或需要处理状态，**When** 状态显示，**Then** 用户能看到安全原因摘要；仅当状态 owner 提供相应操作时，shell 才显示重试或恢复入口。
3. **Given** 面板或模态打开期间出现重要错误，**When** 用户继续操作，**Then** 错误仍可被发现，且不会被错误标记为成功或已保存。
4. **Given** shell 收到未知状态或状态 owner 不可用，**When** 状态区域更新，**Then** 系统显示可理解的退化状态，不泄露路径、原始异常或内部内容。

### Edge Cases

- 用户快速或同时触发多个工具入口时，最终只能有一个明确的活动面板，主要工作区不得重建。
- Escape、触发入口、显式关闭和允许的外部点击在同一次交互中不得造成重复关闭或错误焦点跳转。
- 模态触发元素在模态打开期间消失时，关闭后必须把焦点移到仍存在且合理的工作台位置。
- 工具面板内容为空、不可用、加载失败或提供超长内容时，shell 必须保持主工作区和关闭路径可达。
- 项目在工作台显示期间被外部移动、删除或变为无效时，shell 不得自行扫描、修复或写回项目；它只能呈现 owner 提供的安全状态和后续入口。
- 状态更新乱序、重复或来源暂时不可用时，shell 不得虚构“已完成”或“已保存”。
- 系统主题、减少动态效果或文本缩放在运行期间变化时，工作台不得丢失当前项目、活动面板或主要工作上下文。
- 011 暂未提供所需的共享组件时，002 必须走 foundation 的受控扩展流程，不得复制 primitive、直接绕过其可访问性契约或建立平行设计体系。

## Scope

### In Scope

- 接收 001 成功打开的安全项目摘要，并在项目内工作台中延续稳定项目身份。
- 顶部项目导航、工具入口、主要工作区槽位、单一活动工具面板区域和状态区域的稳定布局与编排。
- 返回 001 启动页的项目级导航，但不重新实现新建、打开、最近项目或重新关联。
- 活动面板的打开、替换、关闭以及触发入口与合理回退位置之间的焦点恢复。
- 使用 011 的共享主题、Typeset、primitives、patterns、Dialog、Tooltip、ScrollArea 和受控扩展规则。
- 键盘可达性、可见焦点、非颜色状态、减少动态效果、200% 文本缩放和 960×640 最小窗口适配。
- 呈现 feature owner 提供的安全状态摘要与可选动作，不拥有这些状态背后的业务事务。

### Out of Scope

- 修改或重新实现 001 的项目身份、创建/打开/重新关联、最近项目、单实例、既有项目能力边界或磁盘副作用。
- 修改或重新实现 011 的主题、外观偏好、排版、基础组件、共享模态/提示行为或既有外观能力边界。
- 持久化活动面板、模态、焦点、选区、滚动位置、窗口布局或“最近编辑位置”。
- 章节、block 编辑、资料库、AI、引用、历史、provider 设置及其保存、重试、恢复业务逻辑。
- 项目内容存储、版本历史、通用设置、任意文件访问或新的 shell 专用跨边界能力。
- 多窗口、远程协作、跨项目搜索和完整路由系统。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在 001 成功返回有效项目摘要后进入工作台，并显示当前项目名称；失败、取消或无效结果 MUST NOT 进入工作台。
- **FR-002**: 工作台 MUST 提供当前项目导航、工具入口、主要工作区槽位、最多一个活动工具面板区域和状态区域。
- **FR-002A**: 工作台 MUST 只呈现已注册且当前可用的工具入口；未注册的未来工具 MUST 完全隐藏，不得显示禁用或可交互占位入口。
- **FR-003**: 工作台 MUST 延续 001 提供的稳定项目身份，且 MUST NOT 创建、修改、删除、重新验证或持久化项目及最近记录。
- **FR-004**: 用户 MUST 能从工作台返回 001 启动页，并继续使用 001 已实现的项目入口；002 MUST NOT 复制这些入口的业务逻辑。
- **FR-004A**: 002 的返回启动页操作 MUST 直接清除当前 shell session 并返回，不得依据展示状态预建 `canLeave`、未保存确认或其他导航阻拦；未来业务 feature 如需阻拦，必须通过其 accepted spec 扩展该政策。
- **FR-005**: 打开、切换或关闭工具面板时，shell MUST 保持主要工作区的稳定身份及其内容、选区、滚动和焦点上下文，不得因 shell 编排而重建主要工作区。
- **FR-006**: 同一时间 MUST 最多只有一个活动工具面板；重复选择当前入口、选择另一入口、Escape 和显式关闭的结果 MUST 可预测且不得重复执行关闭副作用。
- **FR-006A**: Pointer hover MAY 临时预览一个已注册工具面板；指针离开 trigger 与 preview region 后 MUST 使用 200ms 宽限再关闭，以允许指针安全进入面板并避免边界抖动。
- **FR-006B**: 点击或键盘激活 MUST 将对应面板固定打开；固定面板 MUST NOT 因 pointer leave、blur 或计时器自动关闭，并继续遵循再次激活、Escape 和显式关闭规则。
- **FR-007**: 面板关闭后，系统 MUST 优先把焦点恢复到仍存在的触发入口；入口不存在时 MUST 使用已定义的合理工作台回退位置。
- **FR-007A**: 普通非模态工具面板打开时 MUST 保持焦点位于触发入口；键盘焦点按正常 Tab 顺序进入面板。Dialog 继续使用 011 的模态焦点规则。
- **FR-008**: 工作台 MUST 使用 011 提供的 semantic tokens、共享 primitives/patterns、主题、Typeset 和 overlay 可访问性契约，不得建立平行组件或主题体系。
- **FR-009**: 002 需要但 011 尚未公开的共享 UI 能力 MUST 通过 011 的受控扩展流程提出、评审和验证；feature-local 代码只能拥有业务组合与布局。
- **FR-010**: 工作台中的交互入口 MUST 有可访问名称和可见键盘焦点；状态含义 MUST 通过文字或等价语义表达，不得仅依赖颜色、动画、位置或 tooltip。
- **FR-011**: 使用共享模态时，系统 MUST 保证焦点进入与约束、Escape/显式关闭、背景不可误操作、长内容可滚动以及关闭后的合理焦点恢复；具体业务 feature 决定模态何时可关闭及其业务结果。
- **FR-012**: 在 960×640、200% 文本缩放、System/Light/Dark 和减少动态效果条件下，当前项目、主要工作区、工具入口、活动面板关闭路径和重要状态 MUST 保持可达。
- **FR-013**: 工作台 MUST 能呈现 feature owner 提供的进行中、完成、错误和需要处理等安全状态摘要，并且 MUST NOT 把未确认、未知或失败状态显示为成功或已保存。
- **FR-013A**: 多个 owner 同时提供状态时，状态区域 MUST 只显示一个主状态，优先级固定为 `error > needs-action > owner-unavailable > unknown > in-progress > complete`；同级状态使用最新已接受序号并以 sourceId 稳定决胜。
- **FR-014**: 重试、恢复或其他状态动作 MUST 只在对应 feature owner 明确提供时显示，并 MUST 将动作交还该 owner；shell MUST NOT 直接写项目文件、recent index、appearance preferences 或其他持久状态。
- **FR-015**: 未知状态、owner 不可用和安全错误摘要 MUST 采用可理解的退化呈现，且 MUST NOT 暴露绝对路径、项目文件内容、secret 或原始异常。
- **FR-016**: 活动面板、模态、焦点目标、布局模式、选区和滚动位置 MUST 保持为非持久的工作会话状态；本 feature MUST NOT 新增 shell 专用持久数据或跨边界能力。
- **FR-017**: 002 MUST 保持 001 已接受的项目能力边界不变，并消费 011 已接受的外观与共享 UI 契约；shell 本身不得扩大界面层权限。

### Key Entities

- **Workspace Session**：一次已打开项目的非持久工作台会话，关联 001 提供的安全项目摘要与当前 shell 交互状态；不代表新的磁盘记录。
- **Project Summary**：001 成功打开后提供给 renderer 的受限项目身份与显示信息；shell 只消费，不验证或修改项目。
- **Workspace Region**：工作台中具有稳定用途和可访问名称的项目导航、工具入口、主要工作区、活动面板和状态区域。
- **Workspace Slot**：由后续 feature 填充的稳定内容位置；shell 管理布局和持续身份，不拥有槽位内业务状态。
- **Tool Panel**：由工具入口激活的辅助区域，具有稳定标识、触发入口和关闭行为，同一时间最多一个活动实例。
- **Status Summary**：由业务 owner 提供的安全、标准化呈现信息，包括状态含义、严重程度、文字摘要和可选动作；它不是保存事务本身。
- **Focus Return Target**：面板或模态关闭后应恢复焦点的触发入口或已定义回退位置，仅存在于当前工作会话。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 001 已接受的创建、打开、最近项目打开、移动后重新关联、取消和失败场景在接入工作台后保持 100% 通过，且可用项目能力与项目/最近记录副作用不变。
- **SC-002**: 在 100 次面板打开、切换和关闭循环中，主要工作区节点、内容、选区和滚动位置 100% 保持，shell 不造成上下文重建。
- **SC-003**: 工作台的项目导航、所有工具入口、活动面板关闭路径和示例模态操作 100% 可仅用键盘完成，并具有可见焦点与可访问名称。
- **SC-004**: 100% 的面板和模态关闭验证都将焦点恢复到原触发入口或已定义回退位置，且模态打开时背景不可误操作。
- **SC-005**: 在 960×640 与 200% 文本缩放的组合条件下，当前项目、主要工作区、工具入口、活动面板关闭路径和重要错误状态 100% 可到达，无阻断性内容截断。
- **SC-006**: 工作台在 System、Light、Dark 和减少动态效果条件下均通过同一套功能与可访问性场景，且切换条件时不丢失当前项目、活动面板或主要工作上下文。
- **SC-007**: 初始工作台对基础操作、表面、状态、滚动、提示和模态的需求 100% 使用 011 已公开能力或已接受的 foundation 扩展，不存在未经批准的重复基础组件、底层组件绕过或第二套主题规则。
- **SC-008**: 对进行中、完成、错误、需要处理、未知和 owner 不可用状态的验证中，100% 显示非颜色文字/语义结果，且没有路径、原始异常、secret 或项目文件内容泄露。

## Assumptions

- `001-project-foundation` 已接受并实现，是项目身份、创建/打开/重新关联、最近项目、单实例和项目能力边界的权威基线；002 只消费其成功结果。
- `011-ui-foundation` 的 spec、plan、ADR-003 和 UI contract 已接受且实现完成；002 在开始实施前仍须确认 001 migration regression 通过。
- 011 计划中的初始 primitives/patterns 足以覆盖 002 当前已知的通用 UI 需求；若实际 shell 证明需要 Sidebar、Sheet、Tabs 或其他新能力，将按 foundation 扩展流程处理。
- 后续编辑、资料、AI、provider 和历史 feature 各自拥有业务状态、持久化与错误动作，并以 slot 或受限 view model 接入工作台。
