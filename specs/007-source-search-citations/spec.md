# Feature Specification: 资料检索与可追溯引用

**Feature Branch**: `007-source-search-citations`

**Created**: 2026-07-11

**Status**: Draft

**Input**: 从原 `001-ai-writing-workspace` 拆分：检索已处理资料，查看上下文，并把资料片段插入章节引用。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 搜索资料片段 (Priority: P1)

作为作者，我希望用关键词或自然语言查找已处理资料中的相关片段，以便写作时快速找到依据。

**Why this priority**: 可定位的资料片段是引用和 AI 上下文的基础。

**Independent Test**: 在已有处理完成的资料中分别使用关键词和自然语言问题搜索，确认结果包含文本和来源位置。

**Acceptance Scenarios**:

1. **Given** 资料已完成处理，**When** 用户提交搜索，**Then** 系统返回相关文本块、资料名称和解析后位置。
2. **Given** 没有相关结果，**When** 用户完成搜索，**Then** 系统明确显示没有找到匹配内容，而不是展示无依据结果。
3. **Given** 资料仍在处理中或处理失败，**When** 用户搜索，**Then** 系统不把不可用资料作为完整证据返回。

### User Story 2 - 缩小结果并查看上下文 (Priority: P1)

作为作者，我希望按资料名称或标签筛选结果，并查看片段附近的图片、表格和原始页码，以便判断上下文是否准确。

**Why this priority**: 仅显示孤立文本不足以支持可信写作。

**Independent Test**: 为多份资料添加不同标签，筛选搜索结果并打开一个结果，确认附近上下文和原始位置可查看。

**Acceptance Scenarios**:

1. **Given** 搜索返回多份资料的结果，**When** 用户按名称或标签筛选，**Then** 结果只保留符合筛选条件的资料。
2. **Given** 用户打开一个文本片段，**When** 系统展示详情，**Then** 用户能看到解析后位置、原始页码和相关图片/表格上下文。

### User Story 3 - 插入可追溯引用 (Priority: P1)

作为作者，我希望把资料片段插入章节作为引用，并能从正文返回原资料位置。

**Why this priority**: 引用链路把资料检索转化为可验证的写作依据。

**Independent Test**: 从搜索结果插入一个引用到章节，关闭并重新打开项目，确认引用标记和资料回链仍然存在。

**Acceptance Scenarios**:

1. **Given** 用户已打开一个有效搜索结果，**When** 用户选择插入引用，**Then** 正文出现可识别的引用标记。
2. **Given** 正文已有引用，**When** 用户查看引用详情，**Then** 系统显示资料名称、片段内容或位置，并可回到资料片段。
3. **Given** 被引用资料被删除或替换，**When** 用户打开章节，**Then** 引用显示失效状态，并提供重新绑定或移除选项。

### Edge Cases

- 搜索结果缺少文本、来源位置或检索表示时，不得显示为可引用结果。
- 表格或图片与文本片段相邻时，结果详情不得丢失必要上下文。
- 同一片段被多次引用时，系统应保留各正文位置而不重复创建不可区分的引用。
- 用户正在编辑章节时资料被替换，正文不得被静默修改。
- 标签为空、资料名称重复或搜索输入为空时，系统给出明确提示。

## Scope

### In Scope

- 对 `006-source-library-processing` 产出的资料进行关键词和自然语言检索。
- 按资料名称或标签筛选结果。
- 查看文本、Markdown 位置、原始页码、图片和表格上下文。
- 将有效资料片段插入章节并维护引用有效性。

### Out of Scope

- PDF 导入和解析处理。
- AI 任务本身的提交和执行。
- 完整参考文献格式和出版级排版。
- 自动判断引用是否符合学术或版权规范。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为已完成处理的资料提供关键词和自然语言检索。
- **FR-002**: 搜索结果 MUST 包含资料名称、文本块内容、解析后位置和原始资料位置。
- **FR-003**: 系统 MUST 允许用户按资料名称或标签筛选搜索结果。
- **FR-004**: 用户 MUST 能够查看结果附近的图片、Markdown 表格和必要上下文。
- **FR-005**: 系统 MUST 阻止缺少文本、检索表示或来源位置的片段进入可引用结果。
- **FR-006**: 用户 MUST 能够将有效资料片段插入章节正文作为引用。
- **FR-007**: 每个引用 MUST 能显示资料名称、片段内容或位置，并能回到资料片段。
- **FR-008**: 资料被删除或替换后，系统 MUST 将相关正文引用标记为失效。
- **FR-009**: 系统 MUST 提供重新绑定或移除失效引用的明确操作。

### Key Entities

- **搜索结果**：满足查询和筛选条件的资料文本块及其位置上下文。
- **资料片段**：可查看、可引用的文本块及其相关图片、表格和来源位置。
- **引用**：章节内容块与资料片段之间的可追溯关系及有效性状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在包含 500 份已处理资料的项目中，至少 90% 的有效搜索能在 5 秒内返回至少一个带来源位置的结果。
- **SC-002**: 至少 95% 的作者能在 60 秒内从搜索结果定位一个原始资料片段。
- **SC-003**: 100% 插入正文的引用都能显示资料名称和可回溯位置。
- **SC-004**: 100% 被删除或替换资料影响的引用都能显示失效状态。
- **SC-005**: 至少 90% 的作者能在 2 分钟内完成一次搜索、筛选和引用插入。

## Assumptions

- 本 feature 依赖 `004-block-editor` 和 `006-source-library-processing`。
- 首版引用以资料名称、片段内容和位置为基本追溯信息，不实现出版级参考文献样式。
- 搜索结果只使用用户明确已处理完成的资料。
