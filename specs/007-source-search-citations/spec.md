# Feature Specification: 资料检索与可追溯引用

**Feature Branch**: `007-source-search-citations`

**Created**: 2026-07-11

**Updated**: 2026-07-12

**Status**: Draft — refreshed against accepted 001 and 011; requires upstream 004/006 alignment, plan refresh and acceptance

**Input**: 让作者在当前项目已可用的资料中查找依据、核对上下文，并把来源明确的引用插入章节且持续了解其有效性。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查找与写作问题相关的资料 (Priority: P1)

作为作者，我希望使用关键词或自然语言问题搜索当前项目中已可用的资料，以便快速找到可能支持写作的依据。

**Why this priority**: 只有先返回可理解且有来源的结果，筛选、核对和引用才有价值。

**Independent Test**: 在包含多份可用、处理中和失败资料的项目中执行关键词与自然语言搜索，确认结果只来自合格资料，并始终显示来源。

**Acceptance Scenarios**:

1. **Given** 当前项目包含可用资料，**When** 用户提交非空搜索，**Then** 系统返回按相关性呈现的片段，每项都显示资料名称和可理解的来源位置。
2. **Given** 没有合格结果，**When** 搜索完成，**Then** 系统明确显示未找到匹配，并提供调整查询或筛选的提示，不生成无依据结果。
3. **Given** 某些资料仍在处理、失败或仅部分可用，**When** 用户搜索，**Then** 系统只返回其中明确具有可读内容和可靠来源定位的部分，并标识适用限制。
4. **Given** 搜索失败或超时，**When** 用户查看结果区域，**Then** 系统保留查询和筛选条件、说明未完成，并提供重试；旧结果不得伪装成新查询结果。

---

### User Story 2 - 缩小结果并核对上下文 (Priority: P1)

作为作者，我希望按资料筛选结果，并查看片段前后内容、页码、图片或表格上下文，以便判断结果是否真的支持我的写作。

**Why this priority**: 孤立片段可能误导作者；核对来源上下文是可信引用的必要步骤。

**Independent Test**: 在多份具有不同名称和标签的资料中搜索、筛选并打开结果，确认片段、上下文和原始来源位置可核对且切换筛选不会丢失查询。

**Acceptance Scenarios**:

1. **Given** 搜索返回多份资料的结果，**When** 用户按资料名称或标签筛选，**Then** 系统只显示符合当前筛选条件的结果，并清楚展示已应用条件。
2. **Given** 用户打开一个结果，**When** 详情显示，**Then** 用户能看到足以判断含义的前后内容、资料名称和可回到原 PDF 的位置。
3. **Given** 片段附近存在相关图片或表格，**When** 用户查看详情，**Then** 系统展示这些上下文或明确说明无法展示，不把缺失上下文隐藏为完整结果。
4. **Given** 用户从结果返回列表，**When** 列表恢复，**Then** 原查询、筛选和合理的浏览位置保持，用户无需重新开始搜索。

---

### User Story 3 - 插入并维护可追溯引用 (Priority: P1)

作为作者，我希望把已核对的资料片段作为引用插入当前章节，并能从正文返回原资料位置，以便持续验证写作依据。

**Why this priority**: 搜索只有形成稳定、可回溯且不会静默失效的引用关系，才能真正支持写作。

**Independent Test**: 从搜索结果插入引用、保存并重新打开项目，确认正文引用可识别、可查看来源并能回到原片段；再替换或移除来源，确认引用进入明确失效状态。

**Acceptance Scenarios**:

1. **Given** 用户已打开一个合格结果且当前章节可编辑，**When** 用户选择插入引用，**Then** 引用出现在预期编辑位置，并以不打断正文阅读的方式可识别。
2. **Given** 正文已有有效引用，**When** 用户打开引用详情，**Then** 系统显示资料名称、引用片段和来源位置，并允许回到资料上下文。
3. **Given** 用户关闭并重新打开项目，**When** 章节恢复，**Then** 引用仍位于原正文位置并保持与同一资料片段的关系。
4. **Given** 被引用资料已被移除、替换或不再具有可靠定位，**When** 用户查看章节，**Then** 引用显示失效或需要处理状态，正文不被静默改写，并提供重新绑定或移除操作。
5. **Given** 用户尝试重复插入同一片段，**When** 确认插入，**Then** 每个正文位置都可独立识别和操作，同时指向同一来源而不产生含义不明的副本。

### Edge Cases

- 搜索输入为空、仅含空白或超出支持长度时，系统必须给出明确提示，不发起含义不明的搜索。
- 资料名称重复、标签为空或筛选后无结果时，系统必须让用户理解当前条件和清除方式。
- 结果缺少可读内容或可靠来源定位时，不得提供插入引用操作。
- 用户查看结果期间资料状态发生变化时，系统必须在插入前重新确认其引用资格，不得静默插入已失效来源。
- 用户正在编辑章节时来源被替换或移除，正文不得被自动删除或改写。
- 章节不可编辑、没有有效插入位置或插入失败时，系统必须保留正文和搜索上下文并说明恢复方式。
- 在窄窗口、200% 文本缩放、键盘操作、明暗主题和减少动态效果条件下，搜索、筛选、详情、插入和失效引用操作必须保持可达。

## Scope

### In Scope

- 在当前项目中搜索 006 已明确标记为可用的资料内容。
- 关键词和自然语言问题，以及按资料名称或标签筛选结果。
- 查看结果前后内容、资料名称、原 PDF 位置及相关图片和表格上下文。
- 将合格片段插入当前章节并从正文回到来源。
- 引用持久恢复、有效性状态、失效提示、重新绑定和移除。

### Out of Scope

- PDF 导入、内容处理、资料可用资格的生成或修复。
- AI 写作任务、自动生成答案或自动选择引用。
- 自动改写正文以匹配来源，或判断论述是否被来源充分支持。
- 出版级参考文献格式、书目管理和学术引用规范审查。
- 跨项目、互联网或未由用户导入资料的搜索。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户对当前项目中已具备可读内容和可靠来源定位的资料执行关键词或自然语言搜索。
- **FR-002**: 每个搜索结果 MUST 显示可读片段、资料名称和可理解的原始来源位置；缺少任一项的结果 MUST NOT 提供引用操作。
- **FR-003**: 系统 MUST 区分当前查询的进行中、完成、无结果、失败和超时状态，且 MUST NOT 把旧结果或未完成结果表示为当前查询成功。
- **FR-004**: 用户 MUST 能够按资料名称或标签应用、查看、组合和清除筛选，筛选后无结果时系统 MUST 保留查询并说明当前条件。
- **FR-005**: 用户 MUST 能够查看结果的必要前后内容，以及存在时的页码、图片和表格上下文；已知上下文缺失时系统 MUST 明确标识。
- **FR-006**: 从结果详情返回时，系统 MUST 保持当前查询、筛选和合理的浏览位置，除非用户明确清除或开始新搜索。
- **FR-007**: 系统 MUST 只允许把当前仍具引用资格的片段插入可编辑章节；资格变化或插入失败时 MUST 保持正文不变并说明原因。
- **FR-008**: 插入成功的引用 MUST 出现在用户预期的编辑位置，并保持可识别、可查看来源且不遮蔽正文内容。
- **FR-009**: 每个引用 MUST 显示资料名称、引用片段或其摘要和原始来源位置，并允许用户从正文返回对应资料上下文。
- **FR-010**: 保存并重新打开项目后，引用 MUST 保持原正文位置、来源关系和当前有效性状态。
- **FR-011**: 来源被移除、替换或失去可靠定位后，系统 MUST 将受影响引用标记为失效或需要处理，MUST NOT 静默删除或改写正文。
- **FR-012**: 系统 MUST 为失效引用提供重新绑定或移除操作；重新绑定前用户 MUST 能够核对新来源，移除引用 MUST NOT 删除周围正文。
- **FR-013**: 同一资料片段在多个正文位置被引用时，每个引用实例 MUST 能够独立查看、重新绑定或移除，同时保持共同来源可识别。
- **FR-014**: 搜索、筛选、上下文详情、引用状态和操作 MUST 沿用 011 定义的主题、排版、键盘、焦点、非颜色状态和受控共享交互规则。

### Key Entities

- **搜索会话**：当前项目中的查询、筛选、状态和结果浏览上下文。
- **资料结果**：满足当前查询的可读片段、所属资料、原始来源位置、相关上下文和引用资格。
- **引用**：章节中一个可识别位置与资料片段之间的可追溯关系，具有有效、失效或需要处理状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在包含 500 份已可用资料的基准项目中，至少 95% 的搜索在 5 秒内显示结果、明确无结果或可理解失败状态。
- **SC-002**: 100% 可插入的搜索结果同时显示可读片段、资料名称和可回到原 PDF 的来源位置。
- **SC-003** *(post-launch outcome; non-blocking for implementation acceptance)*: 后续可用性测试中，至少 90% 的作者能在 60 秒内从搜索结果定位并核对一个原始资料片段。
- **SC-004**: 在插入、保存、关闭和重新打开测试中，100% 的引用恢复到原正文位置，并显示资料名称和可回溯位置。
- **SC-005**: 对来源移除、替换和定位失效场景，100% 的受影响引用显示非颜色失效状态，且正文不会被静默删除或改写。
- **SC-006** *(post-launch outcome; non-blocking for implementation acceptance)*: 后续可用性测试中，至少 90% 的作者能在 2 分钟内完成搜索、筛选、核对上下文和插入引用。
- **SC-007**: 在仅键盘、System/Light/Dark、减少动态效果、960×640 和 200% 文本缩放条件下，100% 的搜索、筛选、详情、插入和失效引用恢复路径可达。

## Assumptions

- 004 提供可编辑章节和稳定的正文位置语义；006 提供资料可用资格、可读内容和来源定位。两者在本 feature 实施前需完成并接受相应设计。
- 001 提供项目身份与移动边界，002 提供资料和编辑工具的工作台位置，011 提供后续界面共同使用的视觉与交互基础。
- 首版只搜索当前单个项目中由用户导入且已满足资格的资料，不访问互联网或其他项目。
- 引用的首要目标是回溯资料片段；出版级引用样式和参考文献管理留给后续 feature。
