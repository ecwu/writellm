# Data Model: 可移动项目与启动工作区基础

## Versioning policy

项目 manifest、应用级 recent index 与 main-only cleanup receipt index 使用 `kind`
与 `schemaVersion`。本 feature
只实现 `schemaVersion: 1`；未知版本、未知 kind、缺字段或不完整目录只读报错，不
迁移、不自动修复、不写回用户选择的项目目录。

001 不引入内容 `revision`、工作区状态或 renderer 提供的 client mutation ID。
`createdAt` 与 `updatedAt` 在创建时写入相同值，并在 001 内保持不变。唯一活动实例
串行化 recent index 写入；失败操作不自动重试，用户可重新发起同一个 named method。

## Project folder layout

```text
<displayName>.writellm/
├── project.json
└── workspace/
```

`<displayName>.writellm` 是用户可见的文件夹名称，不是稳定身份。项目可以被移动或
重命名；稳定身份只来自 `project.json.projectId`。v1 不创建 Git、content、sources、
ai 或 history 目录。

## Entities

### ProjectManifest

Stored at `project.json`.

| Field | Type | Rules |
|---|---|---|
| `kind` | literal `"writellm.project"` | Required; exact match. |
| `schemaVersion` | integer | v1 only; value `1`. |
| `projectId` | UUID string | Generated by main with `crypto.randomUUID()`; never derived from path/name. |
| `displayName` | string | Non-empty label stored exactly as entered. Creation applies leaf/path safety; open never reconstructs authority from this field. |
| `requiredDirectories` | string[] | v1 exact required entry: `workspace`; unknown future entries are not silently created by this feature. |
| `createdAt` | ISO timestamp | Set once at creation. |
| `updatedAt` | ISO timestamp | Set equal to `createdAt`; immutable in 001. |

The manifest does not contain absolute paths. `displayName` is the project label; the
folder name is generated as `<displayName>.writellm` without trimming, Unicode normalization
or cross-platform reserved-name filtering. NUL, current-platform separators and path-control
segments are rejected because a project name cannot grant path authority.

### RecentIndex

Stored at `app.getPath('userData')/recent-projects.json`; never inside a portable project.

| Field | Type | Rules |
|---|---|---|
| `kind` | literal `"writellm.recent-index"` | Required; exact match. |
| `schemaVersion` | integer | v1 only; value `1`. |
| `records` | RecentRecord[] | Sorted newest first; maximum 5 records. |

### RecentRecord

| Field | Type | Rules |
|---|---|---|
| `recentId` | opaque UUID string | Generated by main; used by IPC, not a filesystem path. |
| `projectId` | UUID string | Stable identity read from the project manifest. |
| `mainOnlyPath` | absolute path | Stored and used only in main; never returned to renderer. |
| `displayName` | string | Last verified display name snapshot. |
| `lastOpenedAt` | ISO timestamp | Sort key and recent-list display value. |
| `availability` | `available \| missing \| invalid \| inaccessible` | Recomputed from disk when the index is loaded/listed. |
| `diagnosticCode` | stable code or null | Safe reason for non-available state; no raw OS exception. |

`RecentRecord` is a pointer cache, not project truth. Removing it deletes only the record.

### CleanupReceiptIndex

Stored at `app.getPath('userData')/pending-project-cleanups.json`; never exposed to renderer.

| Field | Type | Rules |
|---|---|---|
| `kind` | literal `"writellm.pending-project-cleanups"` | Required; exact match. |
| `schemaVersion` | integer | v1 only; value `1`. |
| `receipts` | CleanupReceipt[] | Main-only cleanup authorization hints; not resumable transactions. |

Each `CleanupReceipt` contains `{ finalRoot, token, createdAt }`. It stores no stage, manifest
payload or retry command and cannot resume creation. A corrupt receipt index produces a safe
warning and no filesystem scan or deletion.

### CreateTransaction (ephemeral)

An in-memory main-process record used during creation:

```text
{ finalRoot, cleanupReceipt, manifestTemp, projectId, stage }
```

`stage` is one of `reserving`, `preparing`, `publishing`, `completed`, `failed`. It is not
exposed to renderer. The final root is created atomically with `recursive: false`; any
existing entry produces `PROJECT_EXISTS` and is never replaced. Before root creation, main
persists a cleanup receipt; immediately after reservation it creates a tokenized manifest temp
file matching that receipt. `project.json` is published from that temp file only after
`workspace/` exists.
A failed transaction must not publish a recent record or leave a root that validates as a
project.

On the next startup, main checks only receipt paths and performs best-effort cleanup when the
tokenized temp file matches, no valid manifest exists and the root contains no unknown files.
A valid manifest always wins and causes only the app-owned receipt to be discarded; a missing
marker or ambiguous root is retained and produces a safe warning. Cleanup never scans
unrelated directories or rewrites a valid project.

## Relationships

```text
ProjectManifest 1 ── 0..1 RecentRecord per projectId
RecentIndex    1 ── 0..5 RecentRecord
CleanupReceiptIndex 1 ── 0..* CleanupReceipt (main-only, non-resumable)
```

The same project can have at most one recent record. Reopening updates it; relinking updates
`mainOnlyPath` only after matching `projectId`.

## State transitions

```text
create requested
  ├─ canceled                 → no files, no recent record
  ├─ validation/collision     → no overwrite, no recent record
  ├─ storage failure          → no success result; final root is not valid
  └─ completed                 → available project + recent record

available recent
  ├─ open success              → available, refreshed timestamp
  ├─ external move/delete     → missing/inaccessible/invalid, record retained
  ├─ relink with same ID      → available, path replaced
  ├─ relink with other ID     → PROJECT_ID_MISMATCH, record unchanged
  └─ remove                   → record absent; project untouched

open from dialog
  ├─ new projectId            → new recent record
  └─ existing projectId       → existing path/time updated; recentId preserved
```

## Validation and privacy invariants

- All renderer-originated IDs, names and method arguments are validated in
  main; recent paths are looked up from main-owned state rather than accepted from renderer.
- Project open and relink use only read/stat operations on the project tree. Success and
  failure both leave manifest bytes, timestamps and every other project file unchanged;
  diagnostics never return path, stack, file contents or permissions detail.
- `projectId` is the only identity used for move/relink matching. Folder name and path are
  mutable attributes.
- Recent index writes are atomic and bounded. A missing index is treated as an empty list;
  a corrupt index is treated as an empty in-memory list plus a safe warning without immediate
  overwrite. The next successful create/open may atomically replace it with a valid index;
  index handling must never delete or rewrite project folders.
- No entity contains provider credentials, network URLs, Git state, chapter content or
  absolute paths crossing the preload boundary.
- `requestSingleInstanceLock()` succeeds before repository/index initialization. A secondary
  process does not initialize storage or mutate any entity; it delegates focus to the primary
  and exits.
