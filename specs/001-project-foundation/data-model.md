# Data Model: 可移动项目与启动工作区基础

## Versioning policy

所有 durable JSON 文件使用 `kind` 与 `schemaVersion`。本 feature 只实现
`schemaVersion: 1`；未知版本、未知 kind、缺字段或不完整目录只读报错，不迁移、不
自动修复、不写回用户选择的项目目录。

## Project folder layout

```text
<displayName>.writellm/
├── project.json
└── workspace/
    └── state.json
```

`<displayName>.writellm` 是用户可见的文件夹名称，不是稳定身份。项目可以被移动或
重命名；稳定身份只来自 `project.json.projectId`。v1 不创建 Git、content、sources、
ai 或 history 目录。

## Entities

### ProjectManifest

Stored at `project.json`.

| Field | Type | Rules |
|---|---|---|
| `kind` | literal `"writellm.project"` | Required; exact match. |
| `schemaVersion` | integer | v1 only; value `1`. |
| `projectId` | UUID string | Generated by main with `crypto.randomUUID()`; never derived from path/name. |
| `displayName` | string | Trimmed, 1–120 Unicode characters; no control chars, separators, cross-platform reserved names, trailing space/dot. |
| `requiredDirectories` | string[] | v1 exact required entry: `workspace`; unknown future entries are not silently created by this feature. |
| `createdAt` | ISO timestamp | Set once at creation. |
| `updatedAt` | ISO timestamp | Main-owned; updated with accepted project state changes. |

The manifest does not contain absolute paths. `displayName` is the project label; the
folder name is generated as `<displayName>.writellm` after normalization.

### WorkspaceState

Stored at `workspace/state.json`.

| Field | Type | Rules |
|---|---|---|
| `kind` | literal `"writellm.workspace-state"` | Required; exact match. |
| `schemaVersion` | integer | v1 only; value `1`. |
| `projectId` | UUID string | Must equal the parent manifest projectId. |
| `lastEditedLocation` | `{ kind: "workspace" }` | v1 empty-workspace marker; no document/block IDs exist in this feature. |
| `updatedAt` | ISO timestamp | Main-owned write timestamp. |

This preserves the in-scope recent editing location without inventing a content model.
Later editor features may extend the value only through a new accepted schema/contract.

### RecentIndex

Stored at `app.getPath('userData')/recent-projects.json`; never inside a portable project.

| Field | Type | Rules |
|---|---|---|
| `kind` | literal `"writellm.recent-index"` | Required; exact match. |
| `schemaVersion` | integer | v1 only; value `1`. |
| `records` | RecentRecord[] | Sorted newest first; maximum 5 records. |

### RecentRecord

| Field | Type | Rules |
|---|---|---|
| `recentId` | opaque UUID string | Generated by main; used by IPC, not a filesystem path. |
| `projectId` | UUID string | Stable identity read from the project manifest. |
| `mainOnlyPath` | absolute path | Stored and used only in main; never returned to renderer. |
| `displayName` | string | Last verified display name snapshot. |
| `lastOpenedAt` | ISO timestamp | Sort key and recent-list display value. |
| `availability` | `available \| missing \| invalid \| inaccessible` | Recomputed from disk when the index is loaded/listed. |
| `diagnosticCode` | stable code or null | Safe reason for non-available state; no raw OS exception. |

`RecentRecord` is a pointer cache, not project truth. Removing it deletes only the record.

### CreateTransaction (ephemeral)

An in-memory main-process record used during creation:

```text
{ temporaryRoot, finalRoot, projectId, stage }
```

`stage` is one of `preparing`, `writing`, `finalizing`, `completed`, `failed`. It is not
persisted in the project and is not exposed to renderer. A failed transaction must not
publish a recent record or leave a valid final project root.

## Relationships

```text
ProjectManifest 1 ── 1 WorkspaceState
ProjectManifest 1 ── 0..1 RecentRecord per projectId
RecentIndex    1 ── 0..5 RecentRecord
```

The same project can have at most one recent record. Reopening updates it; relinking updates
`mainOnlyPath` only after matching `projectId`.

## State transitions

```text
create requested
  ├─ canceled                 → no files, no recent record
  ├─ validation/collision     → no overwrite, no recent record
  ├─ storage failure          → no success result; final root is not valid
  └─ completed                 → available project + recent record

available recent
  ├─ open success              → available, refreshed timestamp
  ├─ external move/delete     → missing/inaccessible/invalid, record retained
  ├─ relink with same ID      → available, path replaced
  ├─ relink with other ID     → PROJECT_ID_MISMATCH, record unchanged
  └─ remove                   → record absent; project untouched
```

## Validation and privacy invariants

- All renderer-originated IDs, names, state values and method arguments are validated in
  main; recent paths are looked up from main-owned state rather than accepted from renderer.
- Project open never writes an invalid project directory. Diagnostics identify the stable
  failure category without returning path, stack, file contents or permissions detail.
- `projectId` is the only identity used for move/relink matching. Folder name and path are
  mutable attributes.
- Recent index writes are atomic and bounded. A corrupt/missing index may show an empty
  recent list plus a safe warning; it must not delete or rewrite project folders.
- No entity contains provider credentials, network URLs, Git state, chapter content or
  absolute paths crossing the preload boundary.
