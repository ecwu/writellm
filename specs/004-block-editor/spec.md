# Feature Specification: Block 章节编辑器

**Feature Branch**: `004-block-editor`

**Created**: 2026-07-11

**Status**: Draft

**Input**: 从原 `001-ai-writing-workspace` 拆分：从大纲创建章节，并以 Block 为单位编辑、保存和恢复章节正文。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从大纲创建章节 (Priority: P1)

作为作者，我希望从一个大纲条目开始创建章节，以便把计划转化为可编辑的正文。

**Why this priority**: 章节是作者可以直接交付的最小写作成果。

**Independent Test**: 选择一个尚未开始的大纲条目，创建章节并输入第一段正文，确认章节与条目关联。

**Acceptance Scenarios**:

1. **Given** 大纲条目尚未关联章节，**When** 用户选择开始写作，**Then** 系统创建对应章节并把编辑焦点放在正文区域。
2. **Given** 大纲条目已有章节，**When** 用户再次打开该条目，**Then** 系统打开原章节而不是创建重复章节。

### User Story 2 - 编辑和组织内容块 (Priority: P1)

作为作者，我希望新增、编辑、移动、拆分、合并和删除标题、段落、列表、引用等内容块，以便安全地调整章节结构。

**Why this priority**: Block 操作让作者可以局部修改文章，而不必承担整篇正文被意外改写的风险。

**Independent Test**: 创建包含标题、段落、列表和引用的章节，移动、拆分、合并并删除其中一个块，确认其他块和其他章节不受影响。

**Acceptance Scenarios**:

1. **Given** 章节已有多个内容块，**When** 用户编辑或移动一个块，**Then** 只有目标块及必要的相邻结构发生变化。
2. **Given** 用户拆分或合并块，**When** 操作完成，**Then** 文本顺序和块结构可继续编辑。
3. **Given** 章节中存在资料引用标记，**When** 用户移动正文块，**Then** 引用仍指向原来的正文块或被明确标记为需要检查。
4. **Given** 用户输入或粘贴常见 Markdown 语法，**When** 编辑器处理该内容，**Then** 内容以可继续编辑的内容块呈现；无法完整支持的语法必须有明确提示，不得静默丢失。

### User Story 3 - 保存并恢复章节 (Priority: P1)

作为作者，我希望保存章节并在重新打开项目后恢复正文、块顺序和引用关系。

**Why this priority**: 可靠保存是作者信任编辑器的基础。

**Independent Test**: 编辑一个章节，保存、关闭并重新打开项目，确认内容、顺序和引用关系保持一致。

**Acceptance Scenarios**:

1. **Given** 用户已完成一次编辑，**When** 用户显式保存或离开章节，**Then** 最近一次已保存正文被保留。
2. **Given** 保存失败，**When** 用户返回章节，**Then** 系统显示未保存或错误状态，并提供重试，不得显示为已保存。
3. **Given** 外部工具修改了章节正文，**When** 用户重新打开项目，**Then** 系统提示可能存在外部变更，不得静默覆盖。

### Edge Cases

- 空章节可以创建，但必须显示清晰的空状态。
- 删除唯一内容块时，系统必须保留可继续编辑的空章节结构。
- 拆分或合并包含引用标记的块时，系统不得静默丢弃引用关系。
- 同一块的过期保存不能覆盖更新后的章节内容。
- 外部正文缺少或重复稳定标识时，系统必须要求检查，而不是自动把引用绑定到其他块。
- 导入或粘贴的 Markdown 包含无法表达的扩展语法时，系统不得静默删除其含义。
- 章节包含无法由 Markdown 完整表示的高级内容块时，导出必须给出明确提示或可识别的降级结果。

## Scope

### In Scope

- 从大纲条目创建章节。
- 标题、段落、列表、引用和引用标记等基础内容块。
- Block 的新增、编辑、移动、拆分、合并和删除。
- 章节正文、块顺序和引用关系的保存与恢复。
- 常见 Markdown 语法的输入、粘贴和章节内容导出。

### Out of Scope

- PDF 导入、资料解析和检索。
- AI 任务、提案生成和提案审阅。
- 版本时间线、版本比较和历史恢复。
- 实时协作和多人编辑。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户从大纲条目创建一个关联章节。
- **FR-002**: 章节 MUST 支持标题、段落、列表、引用和资料引用标记等基础内容块。
- **FR-003**: 用户 MUST 能够新增、编辑、移动、拆分、合并和删除内容块。
- **FR-004**: Block 操作 MUST 不改变未选中的章节或资料内容。
- **FR-005**: 每个内容块 MUST 具有可持续识别的稳定标识，以便移动或保存后保持关联。
- **FR-006**: 系统 MUST 保存章节内容、块顺序和可验证的引用关联。
- **FR-007**: 重新打开项目时系统 MUST 恢复最近一次已保存的章节状态。
- **FR-008**: 发现外部修改、标识缺失或重复时系统 MUST 提示用户检查，不得静默重绑定。
- **FR-009**: 保存冲突或失败时系统 MUST 保留当前可恢复内容，并显示重试或重新加载操作。
- **FR-010**: 编辑器 MUST 支持用户输入或粘贴常见 Markdown 语法，并将其呈现为可编辑的内容块；不支持或无法完整表达的语法 MUST 显示明确结果。
- **FR-011**: 用户 MUST 能够将章节内容导出为 Markdown 文件；导出结果用于互操作，不得被误认为能完整表达所有高级内容块。

### Key Entities

- **章节**：与大纲条目关联的文章局部。
- **内容块**：章节中的最小可编辑单元，包含类型、正文、顺序和稳定标识。
- **引用标记**：正文中指向资料片段的可识别关联，实际资料来源由资料 feature 提供。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少 90% 的作者能在 5 分钟内从大纲创建章节并完成首段正文。
- **SC-002**: 在 100 次块移动、拆分、合并和删除测试中，100% 的未选中章节内容保持不变。
- **SC-003**: 在 100 次保存后重新打开测试中，100% 的章节正文和块顺序保持一致。
- **SC-004**: 至少 95% 的作者能在 60 秒内完成一次局部块修改并确认保存状态。
- **SC-005**: 100% 的引用标识异常都能被显式标记，不发生静默重绑定。

## Assumptions

- 本 feature 依赖 `001-project-foundation`、`002-workspace-shell` 和 `003-writing-orientation` 提供项目、工作台和大纲条目。
- 章节正文面向单作者本地编辑，首版不要求多人同时编辑。
- 资料检索和引用插入由 `005-source-search-citations` 补充；本 feature 只负责保留引用标记。
- Markdown 语法支持面向常见结构；扩展方言或高级编辑器结构可能需要明确的降级提示。
- 用户不被承诺章节的内部持久化格式是 Markdown；Markdown 是输入、粘贴和导出的互操作形式。
