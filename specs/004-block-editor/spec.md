# Feature Specification: 章节块编辑器

**Feature Branch**: `004-block-editor`

**Created**: 2026-07-11

**Updated**: 2026-07-12

**Status**: Accepted

**Input**: 让作者从大纲开始撰写章节，以内容块组织和修改正文，并可靠地保存、恢复及交换章节内容。

## Clarifications

### Session 2026-07-12

- Q: 是否接受当前四个用户故事、FR-001–FR-016、验收标准及 Out of Scope 作为 004 的产品范围与验收边界？ → A: 接受。
- Q: 是否接受完整 spec，并在 plan 满足已确认的安全、持久化、互操作、离线、可访问性与跨平台边界后进入任务拆分？ → A: 接受。
- Q: 章节修改应采用哪种保存触发方式？ → A: 自动保存并提供“立即保存”；离开时仅在自动保存尚未成功时提示。
- Q: 哪些情况必须触发“另一个版本”冲突处理？ → A: 仅同一项目中的多个应用内编辑视图产生版本差异。
- Q: 拆分、合并或移动内容块时，资料引用标记应如何归属？ → A: 引用以结构化关系锚定正文片段并随该片段移动；切穿、删除或无法可靠定位时标记为需要检查。
- Q: 首版“常见 Markdown”应支持到什么范围？ → A: 采用已选编辑器的默认 Markdown 子集作为固定基线，不额外支持其他 Markdown 方言。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从大纲开始写章节 (Priority: P1)

作为作者，我希望从一个大纲条目开始创建或打开对应章节，以便把文章计划直接转化为正文。

**Why this priority**: 从大纲到正文是写作工作流的关键衔接，也是使用章节编辑能力的入口。

**Independent Test**: 选择一个尚未开始的大纲条目创建章节并输入首段；再次从同一条目进入时，确认打开的是原章节且内容仍然存在。

**Acceptance Scenarios**:

1. **Given** 大纲条目尚无章节，**When** 作者选择开始写作，**Then** 系统创建一个与该条目对应的空章节，并将作者带到可输入正文的位置。
2. **Given** 大纲条目已有章节，**When** 作者再次从该条目进入，**Then** 系统打开原章节而不创建重复章节。
3. **Given** 章节刚刚创建且尚无正文，**When** 作者查看章节，**Then** 系统显示可继续输入的空状态，而不是错误或缺失状态。

---

### User Story 2 - 编写和重组章节内容 (Priority: P1)

作为作者，我希望以标题、段落、列表和引用等内容块编写、拆分、合并和重排章节，以便在不意外影响其他内容的情况下调整文章结构。

**Why this priority**: 局部、可预测的编辑让作者能放心修改文章，是章节编辑器的核心价值。

**Independent Test**: 在一个章节中创建标题、段落、列表和引用，编辑并重排它们，再拆分、合并和删除部分内容；确认结果符合操作意图，其他章节保持不变。

**Acceptance Scenarios**:

1. **Given** 章节包含多个内容块，**When** 作者编辑一个块，**Then** 目标内容按输入更新，未操作的其他章节保持不变。
2. **Given** 章节包含多个内容块，**When** 作者移动一个块，**Then** 该块的完整内容出现在目标位置，其他块的相对顺序符合作者操作。
3. **Given** 作者在内容块中选择拆分或合并，**When** 操作完成，**Then** 可读文本顺序和格式含义得到保留，并可继续编辑。
4. **Given** 作者删除章节中的最后一个内容块，**When** 删除完成，**Then** 章节保留为可继续输入的空章节。
5. **Given** 正文片段带有资料引用，**When** 作者移动、拆分或合并其内容块且该片段仍可可靠定位，**Then** 引用随该正文片段移动；操作切穿、删除或导致该片段无法可靠定位时，系统将引用标记为需要检查，不得按邻近文字静默重绑定。

---

### User Story 3 - 保存并恢复章节 (Priority: P1)

作为作者，我希望清楚知道章节是否已经保存，并在再次打开项目时恢复最近成功保存的正文、顺序和引用，以免丢失或混淆写作成果。

**Why this priority**: 可验证的保存和恢复是作者信任编辑器并持续使用它的基础。

**Independent Test**: 修改章节并保存，关闭后重新打开项目，确认正文、内容顺序和引用状态一致；模拟保存失败，确认当前内容仍可见且不会被误报为已保存。

**Acceptance Scenarios**:

1. **Given** 作者修改了章节，**When** 保存成功，**Then** 系统明确显示已保存状态。
2. **Given** 章节已成功保存，**When** 作者关闭并重新打开项目，**Then** 系统恢复最近保存的正文、内容顺序和引用状态。
3. **Given** 保存失败，**When** 作者继续停留或返回章节，**Then** 当前编辑内容仍可见，系统明确显示未保存或失败状态并提供重试。
4. **Given** 同一项目中的两个应用内编辑视图打开同一章节，且其中一个视图已保存更新，**When** 另一个基于旧版本的视图尝试保存或重新进入章节，**Then** 系统说明存在差异，并允许作者在不静默丢弃任一版本的前提下选择保留当前编辑或重新载入已保存版本。
5. **Given** 作者修改章节，**When** 自动保存尚未成功且作者准备离开，**Then** 系统提供立即保存、放弃修改或取消离开的选择；最近修改已经自动保存成功时不显示该提示。
6. **Given** 作者修改章节，**When** 作者不等待自动保存而选择“立即保存”，**Then** 系统立即尝试保存并显示保存中、已保存或保存失败状态。

---

### User Story 4 - 输入、粘贴和导出通用文本格式 (Priority: P2)

作为作者，我希望通过常见 Markdown 写法输入或粘贴内容，并能将章节导出为 Markdown，以便与其他写作工具交换内容。

**Why this priority**: 内容交换降低迁移成本，但不应阻碍核心章节写作和可靠保存。

**Independent Test**: 输入或粘贴包含标题、段落、列表和引用的 Markdown，再导出章节；确认支持的结构可编辑且导出内容保持可读，对不能完整表达的内容给出明确提示。

**Acceptance Scenarios**:

1. **Given** 作者输入或粘贴基线 Markdown 子集内的内容，**When** 内容进入章节，**Then** 系统将其呈现为对应的可编辑内容结构。
2. **Given** 粘贴内容包含无法完整支持的语法，**When** 系统处理内容，**Then** 作者在确认结果前能看见哪些内容无法完整保留，且原始含义不得被静默删除。
3. **Given** 章节只包含可由 Markdown 表达的内容，**When** 作者导出，**Then** 导出结果保持文字、顺序和结构含义，并可被常见文本工具读取。
4. **Given** 章节包含 Markdown 无法完整表达的内容，**When** 作者导出，**Then** 系统在导出前说明影响，或在结果中提供清晰可识别且可读的降级表达。

### Edge Cases

- 空章节可保存和重新打开，并始终保持可继续编辑。
- 重复选择“开始写作”不得为同一大纲条目创建多个非预期章节。
- 移动、拆分、合并或删除带引用内容时，不得静默丢失或错误转移引用。
- 保存失败或发现另一版本时，不得把未确认的内容覆盖显示为最近已保存状态。
- 无法识别的章节内容或引用关系不得被自动绑定到看似相近但不确定的内容。
- 粘贴大量内容期间，系统应持续提供明确反馈，且取消或失败后不得留下作者无法理解的部分结果。
- 导出目标不可用或导出失败时，章节原内容不得改变，并应提供可执行的重试提示。

## Scope

### In Scope

- 从单个大纲条目创建或打开其对应章节。
- 标题、段落、项目列表、编号列表、引用和资料引用标记等基础内容。
- 内容块的创建、编辑、移动、拆分、合并和删除。
- 章节正文、内容顺序和引用状态的保存与恢复。
- 未保存、保存中、保存成功、保存失败和版本差异等作者可理解的反馈与处理选择。
- 基线 Markdown 子集的输入、粘贴和单章节导出；基线包括标题、段落、项目与编号列表、任务列表、表格、代码、引用、链接、图片、强调、删除线和硬换行。

### Out of Scope

- 创建和管理资料来源、解析资料或执行检索。
- 搜索资料并新建引用；本 feature 只编辑和保留已存在的引用标记。
- AI 生成、改写、提案和提案审阅。
- 版本时间线、任意历史版本比较与历史恢复。
- 整个项目或整篇文章的批量导入与导出。
- 实时多人协作、评论和权限管理。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许作者从尚无章节的大纲条目创建一个对应章节。
- **FR-002**: 同一大纲条目已有章节时，系统 MUST 打开该章节而不是创建非预期的重复章节。
- **FR-003**: 章节 MUST 支持标题、段落、项目列表、编号列表、引用和资料引用标记等基础内容。
- **FR-004**: 作者 MUST 能够创建、编辑、移动、拆分、合并和删除章节中的内容块。
- **FR-005**: 内容块操作 MUST 保持作者可见的文字顺序和格式含义，并 MUST NOT 改变未操作的其他章节。
- **FR-006**: 删除章节中的最后一个内容块后，系统 MUST 保留一个可继续编辑的空章节。
- **FR-007**: 资料引用 MUST 以结构化关系锚定其对应正文片段，并在该片段可可靠定位时随其移动。操作切穿、删除或导致该片段无法可靠定位时，系统 MUST 将引用标记为需要检查，不得按邻近文字静默重绑定。
- **FR-008**: 系统 MUST 保存并恢复最近一次成功保存的章节正文、内容顺序和引用状态。
- **FR-009**: 系统 MUST 自动保存章节修改，同时提供“立即保存”操作，并让作者能够区分未保存、保存中、保存成功和保存失败状态。
- **FR-010**: 保存失败时，系统 MUST 保留作者当前可见的编辑内容并提供重试。
- **FR-011**: 同一项目中的多个应用内编辑视图编辑同一章节时，系统 MUST 检测基于旧版本的保存；覆盖任一版本前 MUST 提示作者，并提供保留当前编辑或重新载入已保存版本的选择。外部工具直接修改项目文件不属于本 feature 的冲突检测范围。
- **FR-012**: 自动保存尚未成功且作者离开可能丢失修改时，系统 MUST 提供立即保存、放弃修改或取消离开的选择；最近修改已经自动保存成功时 MUST NOT 显示该提示。
- **FR-013**: 系统 MUST 支持由标题、段落、项目与编号列表、任务列表、表格、代码、引用、链接、图片、强调、删除线和硬换行组成的基线 Markdown 子集进行输入、粘贴和导出，并 MUST 将成功转换的内容呈现为对应的可编辑结构；本 feature 不额外支持其他 Markdown 方言。
- **FR-014**: 对无法完整支持的粘贴内容，系统 MUST 在作者确认结果前说明限制，并 MUST NOT 静默删除无法表达的含义。
- **FR-015**: 作者 MUST 能够将单个章节导出为 Markdown，并在导出前获知无法完整表达的内容及其降级影响。
- **FR-016**: 导出或粘贴失败 MUST NOT 改变最近成功保存的章节内容，并 MUST 提供可理解的失败反馈。

### Key Entities

- **章节**：与一个大纲条目对应的文章部分，包含按作者意图排列的内容。
- **内容块**：作者可独立编辑和重组的内容单元，例如标题、段落、列表或引用。
- **资料引用标记**：锚定到具体正文片段的结构化资料出处关联；双中括号等可见 markup 可以作为输入或交换表示，但不是引用关系的唯一依据。资料的查找和插入由其他 feature 提供。
- **章节版本差异**：同一项目中的应用内编辑视图基于旧版本编辑章节，而另一应用内视图已经保存更新时，需要作者决定如何处理的差异。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少 90% 的首次使用者能在 5 分钟内从大纲创建章节、输入首段并确认保存状态，无需外部指导。
- **SC-002**: 在各 100 次移动、拆分、合并和删除验证中，100% 的操作保持预期文字顺序，且 0 次改变未操作的其他章节。
- **SC-003**: 在 100 次保存、关闭和重新打开验证中，100% 的章节正文、内容顺序和引用状态与最近一次成功保存结果一致。
- **SC-004**: 在全部保存失败、版本差异和未保存离开测试中，100% 在任何内容被覆盖或放弃前向作者提供明确状态和处理选择。
- **SC-005**: 在 100 次同一大纲条目重复进入或重复创建操作中，0 次产生非预期重复章节。
- **SC-006**: 至少 95% 的测试参与者能在 60 秒内完成一次内容块重排，并正确判断结果是否已经保存。
- **SC-007**: 对测试集中所有无法完整支持的粘贴或导出内容，100% 在静默信息丢失发生前给出可理解的限制或降级说明。
- **SC-008**: 在全部引用关系异常测试中，0 次将引用静默关联到无关正文。

## Assumptions and Dependencies

- 作者已经打开有效项目，项目具有可用于创建章节的大纲条目。
- 首版面向单作者本地写作；实时多人共同编辑不在范围内。
- 资料引用可以随正文被编辑和保留，但搜索资料、插入新引用和管理资料来源由后续 feature 提供。
- 资料引用的权威关系是正文片段与来源之间的结构化关联；双中括号 markup 仅作为可选输入或交换表示。具体持久化结构属于 plan 或 ADR 决策。
- Markdown 是面向作者的输入、粘贴和导出交换形式；支持范围固定为 FR-013 的基线子集，不额外支持其他 Markdown 方言，也不承诺所有编辑能力都能由 Markdown 完整表达。更换或升级编辑器依赖时必须重新验证该范围的转换兼容性。
- “另一个版本”仅指同一项目中多个应用内编辑视图造成的版本差异；不包含外部工具修改项目文件、浏览完整版本历史或恢复任意历史版本。
